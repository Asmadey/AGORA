# evals — верификатор петли AGORA

Внешний детерминированный верификатор для `/goal`-петли (см. `docs/AGORA_loop_goal.md`).

## Запуск
```
python evals/check.py           # exit 0 = green (Exit A); exit 1 = ещё не green
AGORA_DATASET=/path/to/unified_respondent_sessions.json python evals/check.py
```
- stdout — машинный JSON-отчёт; stderr — человекочитаемая таблица; копия в `evals/last_report.json`.

## Что проверяется
Каждая метрика из `/goal` → отдельная проверка (`pass|fail|skip`). `skip` = подсистема ещё
не построена (честное состояние на pass 0; green недостижим, пока не реализовано).

**Владельцы метрик.** Каждая проверка закреплена за задачей графа через поле `verifies` в
`state/tasks.json` — «ничьих» метрик нет. 10 из 15 проверок сейчас заглушки (`_todo`);
их реализация входит в соответствующую задачу, а не является отдельной работой.

**Фактический прогон на 27.07.2026:** `pass=1 fail=1 skip=13`, green=False.
Работает `secret_scan` ✅; `tasks_done` ❌ (0/31); остальные 13 — skip.

## Граф задач
`state/tasks.json` — **31 задача**: 27 базовых (Ф0–Ф5) + 4 фичи Ф4 (чат по результатам,
«Поделиться», перезапуск с новыми вопросами, файл контекста аудитории). Поля записи:
`id` · `legacy_id` (старая нумерация #9–#35, `= id + 8`) · `subject` · `phase` · `status` ·
`blockedBy` · `verifies` (какие метрики двигает) · `cdd` (падающий тест) · `acceptance`.
Граф проверен на ацикличность, 18 уровней. Петля берёт задачу, у которой все `blockedBy`
в статусе `done`.

## Grounding-корпус и семантика persona_grounding
`data/grounding/unified_respondent_sessions.json` — **на месте, 165 записей**.
Фактические реперы: overall 7.34 · plot 7.58 · acting 8.12 · music 8.07 · cinematography 8.00.
Распределения: возраст 35-44 41% / 25-34 26% / 45-59 17% / 18-24 11% / 60+ 3% / 14-17 2%;
гео центры субъектов 55% / столицы 45% / **«иные НП» 0 из 165**; пол жен 67% / муж 33%.

**Важно:** порог по распределениям (≤0.10) считается **только на эталонном конфиге**
«сгенерируй как в корпусе». Пользовательские прогоны с произвольным составом аудитории
от этой проверки освобождены — иначе продуктовый сценарий выбора аудитории противоречил бы
порогу. **Калибровка баллов (≤1.0) действует всегда.**

## Область secret_scan
Сканируется только `REPO` (сейчас — `apps/web/`). Файлы уровнем выше, включая
`AGORA/env.env` с живым ключом, **не покрыты**. После реструктуризации в монорепо (задача #1)
`REPO` становится корнем репозитория и покрывает всё, что уедет в git.
Вынести `env.env` из-под git до первого коммита.
