# evals — верификатор петли AGORA

Внешний детерминированный верификатор для `/goal`-петли (см. `docs/AGORA_loop_goal.md`).

## Запуск
```
python evals/check.py           # exit 0 = green (Exit A); exit 1 = ещё не green
AGORA_DATASET=/path/to/unified_respondent_sessions.json python evals/check.py
```
- stdout — машинный JSON-отчёт; stderr — человекочитаемая таблица; копия в `evals/last_report.json`.

## Что проверяется
Каждая метрика из `/goal` → отдельная проверка (`pass|fail|skip`). `skip` = подсистема ещё
не построена (честное состояние на pass 0; green недостижим, пока не реализовано).

**Владельцы метрик.** Каждая проверка закреплена за задачей графа через поле `verifies` в
`state/tasks.json` — «ничьих» метрик нет. 10 из 15 проверок сейчас заглушки (`_todo`);
их реализация входит в соответствующую задачу, а не является отдельной работой.

**Фактический прогон на 27.07.2026:** `pass=1 fail=1 skip=13`, green=False.
Работает `secret_scan` ✅; `tasks_done` ❌ (0/31); остальные 13 — skip.

## Граф задач
`state/tasks.json` — **31 задача**: 27 базовых (Ф0–Ф5) + 4 фичи Ф4 (чат по результатам,
«Поделиться», перезапуск с новыми вопросами, файл контекста аудитории). Поля записи:
`id` · `legacy_id` (старая нумерация #9–#35, `= id + 8`) · `subject` · `phase` · `status` ·
`blockedBy` · `verifies` (какие метрики двигает) · `cdd` (падающий тест) · `acceptance`.
Граф проверен на ацикличность, 18 уровней. Петля берёт задачу, у которой все `blockedBy`
в статусе `done`.

**Важно:** порог по распределениям (≤0.10) считается **только на эталонном конфиге**

от этой проверки освобождены — иначе продуктовый сценарий выбора аудитории противоречил бы
порогу. **Калибровка баллов (≤1.0) действует всегда.**

## Сквозной прогон (`e2e_run.py`, задача #22)

Гейты `e2e_short` и `e2e_long` читают артефакты, а `evals/e2e_run.py` их производит.
Прогонщик ходит по HTTP: загружает ролик, собирает аудиторию, запускает задачу, ждёт
`REPORT_READY` и забирает отчёт вместе со всеми карточками персон.

```bash
export BASE_URL=https://agora.example
export CDD_OWNER_EMAIL=... CDD_OWNER_PASSWORD=...   # из .env.local, в git их нет

python3 evals/e2e_run.py --mode short --repeat 3            # golden-сет: 3/3 = trust
E2E_LONG_FIXTURE=/path/long.mp4 \
  python3 evals/e2e_run.py --mode long --timeout 3600
```

**Артефакт пишется только заработанный.** Метрика читает файл и не знает, откуда он
взялся: артефакт, записанный при недоступном сервере или на половине прогона, превратил
бы `e2e_short` из первого гейта проекта в украшение. Поэтому файл создаётся одной
операцией в самом конце, а любой отказ по пути даёт ненулевой код возврата, объяснение
в stderr и **отсутствие файла**.

**`--repeat` — не удобство, а условие доверия.** `passed` и `runs` пишутся в артефакт,
и гейт требует их равенства. Два прогона из трёх — это не «в основном работает», а
«воспроизводится через раз»: между прогонами меняются seed и порядок ответов модели, и
одиночный зелёный прогон не отличает работающий конвейер от везения.

**Чего прогонщик не проверяет.** Вёрстку отчёта. Acceptance задачи называет Playwright,
но все условия CDD — про конвейер (статус, агрегат, число карточек, признак склейки), а
Playwright тянет в `apps/web` бинарные зависимости, запрещённые §6 `CLAUDE.md`. Проверка
интерфейса браузером остаётся ненаписанной, и это сказано вслух, а не спрятано за
зелёной метрикой.

## Фикстуры
- `evals/fixtures/short_60s.mp4` — синтетический smoke-ролик (testsrc+тон). Для проверок
  качества grounding и субъективных оценок заменить на реальный контент.
- `evals/fixtures/long_12min.mp4` — **отсутствует**, нужен для `e2e_long` (задача #22).
  В git не кладётся: сотни мегабайт. Путь передаётся переменной `E2E_LONG_FIXTURE`, и её
  отсутствие — отказ прогона, а не тихая подмена коротким роликом. Подмена дала бы
  зелёный `e2e_long`, никогда не проверявший склейку.

## Область secret_scan
Сканируется только `REPO` (сейчас — `apps/web/`). Файлы уровнем выше, включая
`AGORA/env.env` с живым ключом, **не покрыты**. После реструктуризации в монорепо (задача #1)
`REPO` становится корнем репозитория и покрывает всё, что уедет в git.
Вынести `env.env` из-под git до первого коммита.
