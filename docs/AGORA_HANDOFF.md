# AGORA — Handoff для агента-исполнителя (loop engineering)

Этот документ передаёт проект агенту, который будет **реализовывать AGORA через `/goal`-петлю
в среде пользователя** (VPS TimeWeb / локально). Модель исполнения — B: петлю гоняет
исполнитель, cowork-песочница как раннер не используется.

> пользователя: 21 задача GREEN без пропусков, проект развёрнут и проверен на боевом
> сервере. Изменился и §13 — доступ к модели больше не «выполнено».

> Ревизия 27.07.2026: документ приведён в соответствие с состоянием репозитория и

## 1. Что строим
Self-host мультиарендный сервис синтетических фокус-групп: по соцдем-параметрам
генерируется аудитория AI-персон (цифровых двойников зрителей), они «смотрят» видео и
выдают аналитический отчёт (5 критериев 1–10 + восприятие/NPS/ретеншн/эмоции + групповой
синтез) — усреднённо и по каждой персоне. Заземление на реальный grounding-корпус (165
карточек респондентов из XLS-анкет + DOCX-стенограмм 4 сериалов) и на факты видео
(транскрипт+диаризация+разбор сцен). Позиционирование: «прогноз, а не догадка».

## 3. Целевая архитектура (следствие решений)
```
apps/web (Next.js, Auth.js, XState-визард, SSE, отчёт, Промпт-студия, Настройки)
   │  enqueue task  ▲ SSE progress
   ▼                │
Valkey (очередь/прогресс/кэш) ── Celery worker (services/agent-core)
                                    └ LangGraph pipeline:
                                       probe_and_normalize(ffprobe → proxy, единые таймкоды)
                                       → extract_audio → detect_speech(Silero VAD)
                                       → [WhisperX ∥ pyannote(community-1, по речи)] → merge
                                       → route(short|long)
                                       → sample_frames(PySceneDetect + дедуп + panels)
                                       → analyze_chunks(Qwen VLM, MAP) → stitch(REDUCE)
                                       → pack(Content Pack: полный | компактный)
                                       → evaluate_personas(Qwen, MAP×replication, изоляция)
                                       → qa(judge×2 + эскалация по confidence)
                                       → analytics(агрегат+групповой синтез)
Postgres+RLS (арендаторы, персоны/наборы, портреты, промпты, анкеты, tasks, reports)
MongoDB (chunk JSON, Content Pack, ответы персон, датасет, черновики)
S3 TimeWeb (видео/proxy/аудио/кадры)
Модели: Qwen 3.6 via timeweb OpenAI-совм. API | Whisper+pyannote self-host CPU
```

**Граница данных (Decision Log #13).** Во внешнюю модель уходят только панели кадров,
фрагменты транскрипта и срезы Content Pack. Исходное видео и полный аудиотрек не покидают
контур ни при каких настройках: транскрипция и диаризация идут на своём железе. Узел,
отправляющий наружу байты медиафайла или полный аудиотрек, — дефект.

## 5. Стек и рантайм (TimeWeb)
> ⚠️ Петля исполняется **в среде пользователя** (вариант B). Sandbox-окружение помощника
> её не потянет: нет docker, node 22 вместо 24, python 3.10 вместо 3.14, `api.timeweb.ai`
> недоступен. Доступны только ffmpeg, git, python и pypi.

- Frontend: **Next.js** (Node 24). Backend: **FastAPI + Celery** (Python 3.14).
- Оркестрация: **Docker Compose** на VPS. БД managed: **PostgreSQL 18 + MongoDB 8.0 +
  Valkey 9.1**. Объектное: **S3 TimeWeb, 100 ГБ Standard**.
- VPS (CPU-only, модели по API): по §15 PRD — **8 vCPU / 16 ГБ RAM / 100 ГБ NVMe**.
  Фактически развёрнуто **8 CPU / 12 ГБ** (расширено 04.08.2026 с 4/7.8), свободно 43 ГБ
  диска на 05.08. `large-v3` отработал 162-секундный ролик без OOM. Это не запас:
  на 7.8 ГБ `large-v3` убивался OOM-killer при anon-rss 5.4 ГБ, и голодал заодно веб.
  После расширения и перевода диаризации на подачу волны (вместо пути) пик упал до
  **5102 МБ**, `large-v3` возвращён. `WORKER_CONCURRENCY=1`: Celery prefork держит копию
  модели в каждом процессе, и умолчание 4 делало OOM неизбежным независимо от модели.
- Секреты только из env; новый репозиторий — с чистой истории (в старых репо утекли ключи —
  перевыпустить).

## 9. Правила петли (кратко; полное — в AGORA_loop_goal.md)
- **Верификатор** внешний: `evals/check.py` (exit 0 = green) + независимый LLM-оценщик
  (реализм персон/качество отчёта ≥7, blind). Per-task CDD red→green.
- **Состояние:** `loop-state.json` + граф задач; идемпотентность через seed; резюмируемость
  через LangGraph-чекпоинтер.
- **Остановка:** A — green; B — ≤40 проходов/бюджет; ранний B — одна ошибка ×2.
- **Golden-сеты ×3** на зелёном гейте (3/3 = trust); quick 1× при разработке.
- **Режимы:** DRY_RUN → CANARY (после «ок») → LIVE. Необратимое (git push, деплой, массовые
  платные вызовы, удаление/перевыпуск ключей) — только за гейтом.
