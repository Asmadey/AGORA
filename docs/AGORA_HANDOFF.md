# AGORA — Handoff для агента-исполнителя (loop engineering)

Этот документ передаёт проект агенту, который будет **реализовывать AGORA через `/goal`-петлю
в среде пользователя** (VPS TimeWeb / локально). Модель исполнения — B: петлю гоняет
исполнитель, cowork-песочница как раннер не используется.

> **Ревизия от 27.07.2026.** Документ приведён в соответствие с фактическим состоянием
> репозитория и дополнен пятью фичами, заказанными после интервью (см. §11). Граф задач
> вырос с 26 до **31**. Расхождения, найденные при сверке, и их разрешение — в §12.

## 1. Что строим
Self-host мультиарендный сервис синтетических фокус-групп: по соцдем-параметрам
генерируется аудитория AI-персон (цифровых двойников зрителей), они «смотрят» видео и
выдают аналитический отчёт (5 критериев 1–10 + восприятие/NPS/ретеншн/эмоции + групповой
синтез) — усреднённо и по каждой персоне. Заземление на реальный grounding-корпус (165
карточек респондентов из XLS-анкет + DOCX-стенограмм 4 сериалов) и на факты видео
(транскрипт+диаризация+разбор сцен). Позиционирование: «прогноз, а не догадка».

## 2. Decision Log — зафиксированные решения (12 узлов интервью)

| # | Решение | Итог |
|---|---------|------|
| 1 | Хостинг моделей | Qwen 3.6 (мультимодальная, текст+кадры→JSON) через **OpenAI-совместимый API timeweb.cloud** для VLM и рассуждения персон; **Whisper+диаризация self-host на VPS**. GPU не нужен. |
| 2 | Скоуп режимов | Короткое + длинное строим **одновременно** (пайплайн умеет оба); **первый green-гейт — `e2e_short`**, длинное валидируем следом (`e2e_long`). |
| 3 | Async-хребет | **Valkey(Redis) + Celery + SSE**; LangGraph — внутри Celery-задачи. |
| 4 | Репозиторий | **Один монорепо**, причёсанный под `apps/web` + `services/agent-core` + `packages/shared` + `infra` + `evals` + `data` + `prompts` + `docs`. Общий контракт TS↔Python — **canonical JSON Schema** → генерация TS-типов и Pydantic. |
| 5 | Выборка кадров / стоимость VLM | **PySceneDetect + fallback-интервал + дедупликация по перцептивному хешу + панели по 4 кадра + кэш разбора**. Потолок вызовов Qwen — **управляемый переключатель в Настройках**, дефолт «авто» (без лимита). |
| 6 | Транскрипция | **faster-whisper large-v3 int8 на CPU + параллельные сегменты** для длинного; **Silero VAD** выделяет речь, pyannote **community-1** работает только по речевым участкам одним вызовом (спикеры остаются глобально консистентными); **large-v3-turbo** как fallback-настройка. |
| 7 | Persona DNA | **8-категорийная таксономия** (валидировано экспертом AYA), Big Five **1–5**, ~40–60 полей MVP (расширяемо до 120), «потребитель»→**«зритель»**. Guardrail: ответ ограничен профилем. |
| 8 | Модерируемая дискуссия | **Вариант C**: групповой синтез в Analytics (темы/согласие-несогласие/настроения/цитаты); полный AI-модератор с discussion guide — Phase-2. |
| 9 | Auth / арендатор | **Auth.js self-host**, модель **«команда = арендатор»**, RLS по `tenant_id`, роли owner/member. |
| 10 | Надёжность | **«Перекрытие» (`replication_count`)** — продуктовый параметр запуска (дефолт 1 или 3, отчёт = среднее + разброс/CI, связан с кап-стоимостью). **Golden-сеты ×3 по failure mode** — внутренний гейт верификатора (не пользовательский). |
| 11 | Калибровка | **Статическая в MVP** (сверка с корпусом через `persona_grounding` + хранение версионированных выходов); непрерывная + детект дрейфа — Phase-2. |
| 12 | Исполнение | **Вариант B**: петлю гоняет агент-исполнитель в среде пользователя; данный пакет — вход для него. |
| 13 | Граница данных | Исходное видео и полный аудиотрек **не покидают контур ни при каких настройках**; наружу — только панели кадров, фрагменты транскрипта и срезы Content Pack. |
| 14 | Таймкоды | Единственный источник — **proxy-видео** после `ffprobe`-валидации и нормализации; от него считают транскрипт, границы сцен, кадры и цитаты. |
| 15 | Content Pack | **Две формы**: компактная в массовый прогон респондентов, полная — в контрольный глубокий просмотр по подвыборке. |
| 16 | Стоимость QA | Эскалация на модель большего размера **только по низкому `confidence`**. `QA_ESCALATION_AGENT_ID` необязателен: без него эскалации нет, и это штатный режим. |
| 17 | OCR | Отдельный OCR-контур **не закладывается**: в материале нет субтитров и титров. Пересматривается при контенте с существенной текстовой составляющей. |

Решения 1–12 зафиксированы в интервью. Решения **13–17 добавлены 31.07.2026** по итогам
разбора ТКП стороннего исполнителя — `docs/tkp_agency_review.md`. Там же разобрано, что
взято и что отклонено: их медиаконтур проработан детальнее нашего, наш контур
доказательности (пороговые метрики, калибровка на корпусе) — детальнее их.

## 3. Целевая архитектура (следствие решений)
```
apps/web (Next.js, Auth.js, XState-визард, SSE, отчёт, Промпт-студия, Настройки)
   │  enqueue task  ▲ SSE progress
   ▼                │
Valkey (очередь/прогресс/кэш) ── Celery worker (services/agent-core)
                                    └ LangGraph pipeline:
                                       probe_and_normalize(ffprobe → proxy, единые таймкоды)
                                       → extract_audio → detect_speech(Silero VAD)
                                       → [WhisperX ∥ pyannote(community-1, по речи)] → merge
                                       → route(short|long)
                                       → sample_frames(PySceneDetect + дедуп + panels)
                                       → analyze_chunks(Qwen VLM, MAP) → stitch(REDUCE)
                                       → pack(Content Pack: полный | компактный)
                                       → evaluate_personas(Qwen, MAP×replication, изоляция)
                                       → qa(judge×2 + эскалация по confidence)
                                       → analytics(агрегат+групповой синтез)
Postgres+RLS (арендаторы, персоны/наборы, портреты, промпты, анкеты, tasks, reports)
MongoDB (chunk JSON, Content Pack, ответы персон, датасет, черновики)
S3 TimeWeb (видео/proxy/аудио/кадры)
Модели: Qwen 3.6 via timeweb OpenAI-совм. API | Whisper+pyannote self-host CPU
```

**Граница данных (Decision Log #13).** Во внешнюю модель уходят только панели кадров,
фрагменты транскрипта и срезы Content Pack. Исходное видео и полный аудиотрек не покидают
контур ни при каких настройках: транскрипция и диаризация идут на своём железе. Узел,
отправляющий наружу байты медиафайла или полный аудиотрек, — дефект.

## 9. Правила петли (кратко; полное — в AGORA_loop_goal.md)
- **Верификатор** внешний: `evals/check.py` (exit 0 = green) + независимый LLM-оценщик
  (реализм персон/качество отчёта ≥7, blind). Per-task CDD red→green.
- **Состояние:** `loop-state.json` + граф задач; идемпотентность через seed; резюмируемость
  через LangGraph-чекпоинтер.
- **Остановка:** A — green; B — ≤40 проходов/бюджет; ранний B — одна ошибка ×2.
- **Golden-сеты ×3** на зелёном гейте (3/3 = trust); quick 1× при разработке.
- **Режимы:** DRY_RUN → CANARY (после «ок») → LIVE. Необратимое (git push, деплой, массовые
  платные вызовы, удаление/перевыпуск ключей) — только за гейтом.

## 11. Фичи, добавленные после интервью (ревизия 27.07.2026)
Все четыре новые задачи стоят **после** гейта `e2e_short` (`blockedBy: [22, …]`) — они
входят в `tasks_done`, но не отодвигают первый green.

| # | Фича | Ключевое решение |
|---|------|------------------|
| 28 | **Чат по результатам** | Два режима: «аналитик» (read-only поверх артефактов задачи, только ссылки на таймкоды/цитаты) и «спросить персону» (допрос конкретной персоны из её карточки, та же структурная изоляция, что в #18). **Это отдельный синхронный агент, а НЕ оркестратор** — LangGraph-поток живёт внутри Celery-задачи, умирает вместе с ней и не хранит диалог. Промпты `chat.analyst`, `chat.persona_followup`. Каждое сообщение — платный вызов, учитывается в капе (#27). |
| 29 | **«Поделиться»** | Публичная read-only ссылка: неугадываемый токен ≥128 бит, TTL, revoke, аудит-лог просмотров. Единственный санкционированный обход RLS в системе — отдельная политика на `report_shares` (схема заводится в #2), обязательны негативные тесты (истёкший → 410, отозванный → 410, чужой → 404, никаких мутаций). |
| 30 | **Перезапуск с новыми вопросами** | Переиспользуются `persona_set` **и разбор видео родительской задачи** — VLM не пересчитывается (главная экономия). Память персон — переключатель пользователя, оба режима обязательны: «Допрос» (персона помнит первый прогон, отвечает только на новое) и «Чистый прогон» (вся анкета заново в изоляции). UI объясняет последствия для сопоставимости. Связь через `tasks.parent_task_id`. |
| 31 | **Файл контекста для аудитории** | Не новый механизм: файл дистиллируется в «портрет аудитории» существующим `portrait.distill` (#24) и подаётся в `persona.generate` доп. секцией. **Принцип: корпус приоритетнее файла.** Файл уточняет персон (контекст, лексика, ниша), но не переопределяет распределения по соцдему и калибровку баллов — иначе теряется «прогноз, а не догадка». Проверяется тем, что эталонный `persona_grounding` остаётся green с приложенным файлом. |

Плюс расширение существующей задачи **#6**: карточка персоны показывает **все** атрибуты
(все 8 категорий DNA, а не подмножество из 8 полей) + её ответы и цитаты в контексте
конкретного исследования. CDD сверяет отрендеренные поля с canonical JSON Schema.
