## Решения владельца, которые нельзя пересматривать молча

1. Обязательная анкета — ровно пятнадцать вопросов заказчика. Удержание и доля
   просмотра из обязательных вышли и не возвращаются.
2. Вопрос 9: оператор выбирает ТЕМЫ целиком, все подтемы включаются, подвопросы
   вопроса 11 добавляются автоматически.
3. Опрос персоны — один вызов модели.
4. Базовым критериям запрещена любая шкала кроме 0–10.
5. Редактор вариантов в конструкторе — писать сейчас.
6. Доля просмотра убрана и из обязательных вопросов, и из интерфейса отчёта.
7. Неполный ответ — **ошибка**. Закрывается тремя мерами в связке: грамматика
   ответа, правило QA `coverage`, переспрос.
8. Эхо ценностей (p = 0.0001) дефектом не считается; диаграмма вопроса 8
   остаётся. Открыт другой вопрос — опирается ли ответ на ролик; проверяется
   двумя разными роликами на одном наборе персон, замер не проводился.

## Этап 2. Конструктор анкеты

Файл — `apps/web/components/agora/SurveyBuilder.tsx`.

**Что сломано прямо сейчас.** Перечень типов предлагает пять, включая
`single_choice`, `multi_choice` и `matrix_single`, а редактора вариантов и строк
нет. Кнопка «Готово» при этом активна. Оператор собирает анкету, которую
`PUT /api/surveys` отвергает (`survey-validator.ts`: «закрытому вопросу нужно не
меньше двух вариантов»), и починить её в интерфейсе нечем. Это регрессия,
внесённая свёрткой шести типов в пять.

**Что сделать.**

1. Редактор вариантов: добавление, удаление, перестановка, подпись. Для
   `multi_choice` — поле `maxChoices` и отметка «служебный вариант»
   (`exclusiveOptionIds`): служебный выбирается только в одиночку.
2. Редактор строк для `matrix_single`.
3. Раздел «Обязательные»: пятнадцать вопросов заказчика, нередактируемые,
   визуально отделены от своих. Данные брать из `apps/web/lib/customer-survey.ts`
   — он уже написан и покрыт тестами, но **не импортирован ни одним
   компонентом**. Второй копии пятнадцати вопросов в TSX не заводить: в этом
   репозитории так уже появились четыре копии перечня типов и две копии перечня
   ценностей, и одна из них полтора месяца молча отставала от схемы.
4. Выбор тем вопроса 9 галочками: `themesOf(9)` и `withSelectedThemes([...])` из
   того же модуля. Проверить максимум — все десять тем, 43 подтемы, 11
   подвопросов; архитектура обязана это выдержать.
5. Предупреждение о неграфичных типах: у `QUESTION_TYPES` уже есть флаг
   `chartable`, у открытого он `false`. Показать это при выборе типа, а не после
   прогона.

**Чего не делать.** Не возвращать в `BASE_QUESTIONS` вопрос о доле просмотра и
не делать обязательные вопросы редактируемыми.

## Этап 3. Остаток по опросу

Сделано: грамматика ответа (`respondent/answer_schema.py`, замерена — 67 полей
из 67), правило `coverage` с `source: "rule"`, подсказка переспроса вида
`coverage`, потолок переспроса поднят до 40.

**Что осталось.**

1. Детерминированные правила QA на закрытые ответы. Разбор (`parse_field_answer`)
   уже находит вариант не из списка, превышение `maxChoices`, служебный вариант
   рядом с содержательным и балл вне шкалы — но в вердикты QA это не заведено.
   Сейчас такой ответ молча не голосует в `survey_stats` (счётчик `errors`), а
   должен ещё и попадать в переспрос.
2. Проверить связку целиком на живом прогоне: неполный ответ → вердикт
   `coverage` → переспрос → второй круг QA → агрегат. По кускам всё под тестами,
   вместе не проверялось ни разу.

## Грабли этого куска работы

**Один класс дефектов дал здесь пять случаев подряд**, и все пять выглядели
правдоподобными числами, а не отказами:

| Где | Разошлись |
|---|---|
| `qa/checks.py` | правило искало базовые баллы в `survey_answers`, а они в `scores` |
| `qa/checks.py` | то же с вопросом о доле просмотра — он в `perception` |
| `qa/checks.py` | покрытие искало идентификатор вопроса, а матрица адресуется строкой |
| `survey.py` | `answerable_fields` выдавала `q09-themes/t1-1` — форму, которой не пишет и не читает никто |
| `respondent/run.py` | читатель знал плоскую матрицу и не знал вложенной, а так отвечали 13 персон из 20 |

Отсюда два правила, каждое из которых стоило прохода:

- **Прибор не разбирает ответ сам.** Проба зовёт `_answers_to_map` — тот же код,
  которым ответ читает продукт. Свой разбор в приборе означает, что прибор
  меряет себя. Четыре подряд «результата замера» оказались артефактами чтения.
- **Адрес поля — это то, что промпт печатает в скобках.** Держит
  `test_survey_render.py`: он сверяет `answerable_fields` с выводом
  `render_questions`, а не описывает форму словами.

**Обход прячет дефект надёжнее, чем его отсутствие.** Проба делила адрес по «/»
и работала — поэтому расхождение прожило до тех пор, пока не понадобилась схема.

**Codex CLI** запускается обычной локальной командой: `codex exec --cd <каталог>
"<промпт>"`, без `--sandbox` и без `timeout`. Если он говорит «командный раннер
недоступен» — не хватает симлинка
`/usr/local/bin/codex-code-mode-host` на `/Applications/ChatGPT.app/Contents/Resources/codex-code-mode-host`.
С полным доступом он нашёл два дефекта, которых не увидели ни хост-агент, ни
второй ревьюер.

## Как проверять

```bash
cd services/agent-core && pytest -q --ignore=tests/test_audience_identity.py && ruff check .
cd apps/web && npx tsc --noEmit && npm test && npx eslint .
python3 evals/tests/test_task09_audience.py   # GREEN pass=27
python3 evals/tests/test_task10_survey.py     # GREEN pass=33
```

`tests/test_audience_identity.py` требует `celery`, которого на хосте нет: он
живёт в образе воркера (§9), туда тест и едет через `./evals/run_in_worker.sh`.

Замер анкеты — на сервере, в образе воркера, парой прогонов:

```bash
ssh root@185.154.194.125
cd /tmp/agora-probe && git fetch origin <ветка> && git checkout FETCH_HEAD
ENV_FILE=/root/AGORA/.env.local ./evals/run_in_worker.sh -- \
  python evals/analysis/survey_load_probe.py --live --schema \
  --pack-task 4cc3e7f8-3063-42f7-b0ab-a60932e817a2 -n 20
```

Без `--schema` — контрольный прогон. Мерить имеет смысл только парой: один и
тот же пакет, те же персоны, разница в одном флаге.

**Перед пересборкой воркера** проверить, что ни один прогон не идёт (§3-бис):

```bash
docker exec agora-postgres-1 psql -U agora -d agora \
  -c "SELECT status, count(*) FROM tasks GROUP BY status;"
```
