## 0. Главный вывод, из которого следует всё остальное

За один проход нашлось **шесть дефектов, делавших продукт нерабочим**, и ни один
из них не был виден в CI. Общая причина одна: тест печатает `GREEN` при
ненулевом числе `SKIP`, и по выводу нельзя отличить «проверено» от «пропущено».

Хронология одного маршрута загрузки видео показывает механику:

| Дефект | Почему не был виден |
|---|---|
| Подпись SigV4 считалась по пути без бакета | кейс с настоящей заливкой пропускался |
| `S3_*` не передавались сервису `web` | тест упирался в 401 раньше |
| В веб-образе нет python3 | кейс дистилляции пропускался |
| Не задан `AGORA_REPO_ROOT` | то же |
| В веб-образе нет ffmpeg | кейс ffprobe пропускался |
| Пароли открытым текстом в тестах | `evals/` исключён из `secret_scan` |

Первый из них означает, что **загрузка видео не работала ни разу за всё время
существования проекта**. Задача #8 при этом стояла `done`.

Поэтому пункт 1 плана — не про эти шесть дефектов, а про то, что позволило им
дожить до сегодня.

## 1. Гейты: сделать пропуск видимым

### 1.1. Тест не может быть зелёным, если пропущен пункт `cdd`

Сейчас `GREEN` печатается при `n_fail == 0` независимо от числа `SKIP`. Значит
тест, который ничего не проверил, неотличим от теста, который проверил всё.

**Что делать.** Ввести в тестах явную привязку проверки к пункту `cdd` и
запретить зелёный вердикт при пропущенном пункте. Формат вердикта:
`GREEN` только при `skip_cdd == 0`; при пропущенных пунктах `cdd` — `AMBER` с
перечислением, что именно не проверялось, и ненулевым кодом возврата в режиме
живой среды.

**Почему не «просто запретить SKIP».** Отсутствие среды — законная причина
пропуска, и она обязана оставаться. Незаконна другая ситуация: пропуск, не
обусловленный проверкой окружения. Таких за проход нашлось три (`skip for now` в
#7, две безусловные строки в #24).

### 1.2. Запретить безусловный `skip`

Проверка на уровне `check.py`: в `evals/tests/*.py` не должно быть вызова `skip`,
который не находится внутри ветки, проверяющей переменную окружения или наличие
внешнего ресурса. Реализуется разбором AST, а не регуляркой.

### 1.3. `secret_scan`: снять исключение `evals` и добавить шаблон пароля

Два независимых дефекта, каждого хватило бы:

- в `skip_dirs` стоит `"evals"` — весь каталог тестов не сканируется;
- ни один шаблон не ловит ключ `password` со строковым литералом справа —
  покрыты только ключи API и пароли внутри строк подключения.

Оба пароля, пролежавшие в `evals/tests`, прошли мимо метрики по обеим причинам.

### 1.4. Защитить `main`

Четыре PR были слиты при красном гейте. Обязательные проверки `web`, `worker`,
`cdd`, `secrets` закрывают класс целиком. Действие владельца репозитория.

## 2. Развёртывание воркера

Контейнер `worker` **никогда не создавался**: `docker compose ps -a` показывает
только `postgres` и `web`. Определение сервиса в compose есть и выглядит полным
(переменные, том под кэш весов, `concurrency`), Dockerfile тоже — с ffmpeg,
libgomp1, libsndfile1 и непривилегированным пользователем.

Значит работа не в написании, а в проверке: собрать, поднять, убедиться, что
Celery видит брокер и выполняет задачу.

### Что мешает прямо сейчас

- **`VALKEY_URL`** объявлен обязательным. Managed Valkey на TimeWeb в
  `.env.local` есть — надо убедиться, что он доступен с VPS.
- **Нет healthcheck** у сервиса `worker`. Без него `compose_health` не отличит
  поднятый воркер от упавшего. Добавить `celery inspect ping`.
- **Нет задачи, на которой это проверяется.** В `celery_app.py` есть `agora.ping`
  — годится как первая цель.

### Риск, который надо назвать заранее

VPS — 2 vCPU / 4 ГБ при 8/16 по §15 PRD. Пока воркер пустой, это не проявится.
На задаче #15 приедут faster-whisper large-v3 и pyannote с torch, и нехватка
памяти проявится как случайный OOM-килл посреди прогона, а не как внятная
ошибка. Решать до #15, а не после.

## 3. Модуль `media` (#14)

### Ложная зависимость в графе

В графе `#14 blockedBy [13]`, то есть препроцессинг ждёт оркестратор LangGraph.
Кодом это не подтверждается: `cdd` задачи #14 — целиком про ffprobe, proxy-видео,
таймкоды и PySceneDetect, там нет ничего про граф исполнения. Оркестратор
*вызывает* медиа-модуль, а не наоборот.

Это тот же случай, что ребро `#25 → #24`, снятое 03.08 по той же причине.

**Следствие важное:** если ребро снять, `#14` можно делать немедленно, и это
разблокирует `#15` и `#16` — то есть всю ветку транскрипта и разбора кадров, не
дожидаясь цепочки UI `#6 → #9 → #11 → #13`.

Ребро снимается отдельным PR с обоснованием, как это уже делалось.

### Состав модуля

`services/agent-core/agent_core/media/` — по `cdd` задачи #14:

| Функция | Назначение | Проверяется |
|---|---|---|
| `probe(path)` | параметры контейнера и потоков | файл без видеодорожки → внятная ошибка, не падение |
| `make_proxy(src, dst)` | proxy-видео для разбора | постоянный фреймрейт, `start_time == 0` |
| `extract_audio(src, dst)` | дорожка для #15 | таймкоды совпадают с proxy с точностью до кадра |
| `segment(src, seconds)` | нарезка длинного видео | границы сегментов без потери кадров |

Зависимости: только ffmpeg/ffprobe как внешние процессы. Python-пакетов не
требуется — это важно, потому что ставит модуль на критический путь до тяжёлых
зависимостей #15.

## 6. Чего в этом плане намеренно нет

**Переписывания дистилляции на очередь.** Маршрут `/api/portraits/distill`
запускает python3 из веб-контейнера — архитектурно это место для Celery-задачи.
Но пока воркер не развёрнут и не проверен (стадия C), перенос туда заменит
работающий код на неработающий. Возвращаться сюда после стадии C.

**Догона `#14` до полной функциональности за один заход.** `cdd` требует
совпадения таймкодов proxy и аудио с точностью до кадра — это проверяется только
на настоящем ролике со звуком. Такой ролик нужен от владельца: сгенерированный
чёрный квадрат без звуковой дорожки для этого не годится.
