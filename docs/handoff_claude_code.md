## Что делать — по порядку

### 1. Достать лог красного CI и починить причину

Четыре PR подряд слиты при красном гейте с формулировкой «дело в отсутствующем секрете».
Причина до сих пор не установлена. Задание `cdd` воспроизводилось локально четырьмя
способами (чистый venv с `pglast`; плюс `jsonschema`; плюс `datamodel-code-generator` 0.71;
свежий клон) — зелёное во всех четырёх. Значит дело в окружении раннера или в другом задании.

`gh run view --log-failed` без аргументов открывает интерактивный выбор и подвешивает
терминал — вызывай только с номером прогона и с `| tail`:

```bash
gh run list --limit 10 --json databaseId,status,conclusion,headBranch,displayTitle \
  --jq '.[] | "\(.databaseId) \(.conclusion) \(.headBranch) \(.displayTitle)"'
gh run view <ID> --json jobs --jq '.jobs[] | "\(.databaseId) \(.conclusion) \(.name)"'
gh run view --job <JOB_ID> --log | tail -150
```

Разобрав причину: если дефект в воркфлоу — правь `.github/workflows/ci.yml` отдельным
маленьким PR и сливай его первым. Если нужен секрет в репозитории — это решение человека,
останавливайся и докладывай.

**Красный CI блокирует слияние.** Объяснение, почему CI неправ, вердиктом не является.

## Что нельзя без человека

Force-push и удаление удалённых веток. `reset --hard`, `checkout --`, `clean -fd`,
`stash drop` при непустом рабочем дереве — сначала `git status`, потом команда.
Слияние при красном CI. Добавление секретов в GitHub Actions. DDL руками в обход
нумерованной миграции. Удаление данных в живой базе, ротация ключей. Массовые платные
вызовы моделей — гейт CANARY: не больше трёх реальных вызовов.

Останавливайся и докладывай, если одна и та же ошибка повторилась дважды или две попытки
одного фикса не удались: диагноз неверен, ищи предположение под обоими.

## Грабли, на которые уже наступали

Полный список в `CLAUDE.md` §6. Самое дорогое:

`SET LOCAL app.tenant_id = $1` не работает — только `set_config('app.tenant_id', $1, true)`.
`pg` игнорирует поле `ssl`, если задан `connectionString`: путь к сертификату передавать
параметром `sslrootcert` внутри строки. Ноль строк из непустой таблицы — это RLS, лечится
политикой для роли, не снятием `FORCE` и не `BYPASSRLS`. `ALTER ROLE … NOSUPERUSER` на
managed требует суперпользователя, которого там нет. Нативные npm-модули в `apps/web`
запрещены: каталог `node_modules` общий между macOS и Linux. Вложенные зависимости
воркспейса не попадают в корневой `node_modules` — Dockerfile обязан копировать
`apps/web/node_modules` отдельно. Внутри контейнера `localhost` резолвится в `::1`, а
next-server слушает IPv4 — в healthcheck нужен `127.0.0.1`.

**Отдельный класс, встретился трижды.** Проверка, которая никогда не исполнялась, но
считалась пройденной: в тесте #4 импорт несуществующего `Model` уходил в `SKIP`; в тесте #27
JSON-ключи без кавычек давали `NameError`; в тесте #7 читалась несуществующая переменная
`MONGODB_URI`. Все три задачи при этом стояли `done`. Если проверка пропущена — разберись,
это отсутствие среды или дефект теста. Отсутствие среды даёт SKIP; всё остальное — FAIL.
