## Открытый блокер: docker-сборка web

`Can't resolve 'mongodb'` при сборке образа. **Диагноз проверен, заново не расследовать.**

`mongodb@7.5.0` установлен только как `apps/web/node_modules/mongodb` — npm не поднял его в
корневой `node_modules`. А `infra/web.Dockerfile` копирует из deps-стадии исключительно
`/repo/node_modules`; копирование `apps/web/node_modules` убрали коммитом `310f805` в
предположении, что `npm ci --workspaces` складывает всё в корень. Для `mongodb`
предположение неверно.

Лечится восстановлением копирования вложенных зависимостей воркспейса в builder-стадии:

```dockerfile
COPY --from=deps /repo/apps/web/node_modules ./apps/web/node_modules
```

Точечный `COPY` на конкретный пакет не годится: в runner-стадии уже висит такой костыль для
`hash-wasm` — это второй случай той же болезни, третий будет.

Дело **не** в lockfile, **не** в доступе к MongoDB и **не** в пароле от неё.

## Что уже стоило проходов — не повторять

Полный список в `CLAUDE.md` §6. Самое дорогое:

`SET LOCAL app.tenant_id = $1` не работает — только `set_config('app.tenant_id', $1, true)`.
`pg` игнорирует поле `ssl`, если задан `connectionString` — путь к сертификату передавать
параметром `sslrootcert` внутри строки. Ноль строк из непустой таблицы — это RLS, лечится
политикой для роли, не снятием `FORCE` и не `BYPASSRLS`. `ALTER ROLE … NOSUPERUSER` на
managed требует суперпользователя, которого там нет. Нативные npm-модули в `apps/web`
запрещены. Красный CI блокирует слияние — если CI неправ, сначала отдельный PR, чинящий CI.

## Нерешённые вопросы к человеку

Красный CI на заданиях `cdd` и `worker` — причина неизвестна, локально оба воспроизводятся
зелёными тремя способами. Нужен лог упавшего шага.

В истории origin остаются пароли из PR #3 и анкеты респондентов из `docs/quiz` (ПДн).
Требуется `git filter-repo` или BFG; каждый новый коммит удлиняет то, что придётся
переписывать. Владелец решил ключи не перевыпускать — решение зафиксировано.

`main` не защищён: force-push и удаление возможны. Стоит включить правило с обязательными
проверками `web`, `worker`, `cdd`, `secrets`.

VPS заказан 2 vCPU / 4 ГБ против 8 / 16 в §15 PRD. На текущих задачах не мешает, упрётся на
#15, когда на воркер приедут faster-whisper и pyannote с torch, — и проявится как OOM-килл
посреди прогона, а не как нехватка памяти.

У локального PostgreSQL в контейнере нет регулярного резервного копирования — есть только
разовый дамп, снятый перед миграциями.
