# Интерфейс AGORA: как он устроен и как собрать его заново

Документ отвечает на два вопроса: **что нужно построить**, чтобы получился
интерфейс AGORA, и **как подключить к нему backend**, который уже написан.

Он сверен с кодом на 10.08.2026. Редакция от 07.08 была написана по памяти и
ошибалась в основах — `pnpm` вместо `npm`, каталог `src/`, которого нет,
черновики визарда в Postgres вместо Mongo. Ошибки такого рода читаются
правдоподобно и обнаруживаются через час сборки, поэтому здесь каждое
утверждение — из репозитория, а не из общей практики.

**Это описание того, что есть, а не список пожеланий.** Что сказано в настоящем
времени — лежит в коде и собирается. Незакрытое названо прямо и с номером задачи.

**Что читать рядом:** `docs/ARCHITECTURE.md` — почему система устроена так;
этот файл — что именно построить. Пересечение сведено к минимуму намеренно:
одно знание в двух местах расходится молча.

## 0. Чего этот интерфейс не делает

Проще начать с границ — они объясняют половину решений.

**Интерфейс не считает.** Ни средних, ни NPS, ни процентов. Всё числовое
приходит посчитанным из воркера. Экран, пересчитывающий агрегат «для удобства»,
рано или поздно покажет число, отличное от отчёта, и различить, какое из них
правильное, будет нечем.

**Интерфейс не ходит в воркер.** Между ними нет HTTP. Веб кладёт задачу в
очередь Valkey и читает результат из Postgres и Mongo; воркер пишет прогресс в
Valkey. Разбор часового ролика занимает десятки минут — запрос такой длины это
таймаут прокси, потерянный ответ при перезапуске и невозможность показать
прогресс.

**Интерфейс не фильтрует чужие данные руками.** В Postgres это делает RLS, в
Mongo — обязательный фильтр по `tenant_id`, который берётся из сессии. Фильтр,
написанный в компоненте, забывается в одном запросе из тридцати.

## 1. Стек и стартовая установка

Пакетный менеджер — **npm** с workspaces. `pnpm` в этом репозитории не
используется, `package-lock.json` лежит в `apps/web`.

```bash
npm ci                      # из корня монорепо, ставит все workspace
npm run build -w apps/web   # next build
npm run typecheck -w apps/web
npm run lint -w apps/web
```

Скрипты `apps/web/package.json`: `dev`, `build`, `start`, `lint`, `typecheck`,
`clean`. Никакого `pnpm exec shadcn` — примитивы уже в репозитории.

| Слой | Выбор | Существенное |
|---|---|---|
| Фреймворк | Next.js 15.4, App Router, React 19 | серверные компоненты по умолчанию |
| Язык | TypeScript, `strict` | пути `@/*` → корень `apps/web`, **не** `src/` |
| Стили | Tailwind **v4** | токены в `@theme` внутри `app/globals.css`, не в `tailwind.config.js` |
| Примитивы | shadcn/ui поверх Radix | `components/ui/`, руками не правятся |
| Состояние визарда | xstate 5 | `lib/wizard/machine.ts` |
| Аутентификация | Auth.js (next-auth 5 beta), JWT | `lib/server/auth.ts`, стратегия jwt |
| Пароли | **hash-wasm** | WebAssembly. Нативные модули в `apps/web` запрещены |
| Postgres | `pg` | только из `lib/server/db.ts` |
| MongoDB | `mongodb` | только из `lib/server/mongo.ts` |
| Valkey | `redis` | `lib/server/valkey.ts` |
| Графики | recharts | |
| PDF | jspdf + html2canvas | экспорт отчёта — P2 |

**Нативные npm-модули запрещены.** `node_modules` общий для всех, кто открывает
папку, а нативный пакет собирается под платформу: установленный из Linux ломает
запуск на macOS. Нужен argon2 — берётся `hash-wasm`. Это правило уже стоило
одного прохода.

**`@google/genai` в зависимостях есть, но использовать его не надо** — остаток
прототипа, помеченный в `.env.example` как выпиливаемый.

## 3. Тема и токены

Tailwind v4 ушёл от `tailwind.config.js` к директиве `@theme` в CSS. Значения —
CSS-переменные, поэтому переключаются в рантайме.

```css
/* app/globals.css */
@import "tailwindcss";

@theme {
  --color-background: hsl(222.2 84% 4.9%);
  --color-foreground: hsl(210 40% 98%);
  /* … 14 токенов: primary, secondary, muted, accent, destructive, border,
     input, ring, card, popover + радиусы */
}
```

Тёмная тема — база, а не переключатель: `<html lang="ru" className="dark">` в
`app/layout.tsx`. Светлой темы нет, и токены под неё не считались.

Модели устаревают именно на этом месте: агент без актуальной документации
уверенно напишет `tailwind.config.js`, и это будет выглядеть правильным.

## 4. Экраны

### Визард запуска — `app/studies/new`

Машина в `lib/wizard/machine.ts`. **Семь состояний**, видимых шагов в шапке —
четыре:

```
content → audience → survey → overlap_params → summary → launch → progress
└──── «Контент» ────┘ «Аудитория» «Опрос»      └── «Резюме» ──┘
```

Расхождение намеренное: `overlap_params`, `launch` и `progress` — состояния
процесса, а не страницы, на которые пользователь возвращается.

У каждого шага есть предикат обязательных полей (`REQUIRED` в машине). У шага
`audience` их две ветки: выбран готовый набор — критерии не нужны; генерация —
обязательны размер, возраст, гео и пол. Пол обязателен потому, что в корпусе он
распределён 110/55 и участвует в калибровке.

**Черновик визарда лежит в MongoDB**, коллекция `wizard_drafts`, доступ через
`GET|PUT /api/wizard/drafts/{projectId}`. Не в Postgres. Сохранение
идемпотентно — upsert по `(tenant_id, project_id)`, повторная отправка того же
шага не плодит записей, и перезагрузка страницы восстанавливает состояние.

### Прогресс — `app/runs/[id]/progress`

`EventSource` на `GET /api/tasks/{id}/progress`. Порядок обязателен: первым
событием приходит **снимок** текущего состояния, дальше — изменения по подписке.
Pub/Sub ничего не помнит, и подписчик, пришедший к середине прогона, без снимка
видел бы пустой экран минуты — неотличимо от зависшего прогона.

Каждые 20 секунд сервер шлёт комментарий `: ping`, иначе прокси закрывает
молчащее соединение на длинной транскрипции.

Список этапов не хардкодится: `lib/pipeline-nodes.ts` читает
`packages/shared/pipeline/nodes.json` — тот же файл, по которому воркер строит
граф. Две копии списка разошлись бы молча, и шкала показывала бы не тот этап.

### Отчёт — `app/runs/[id]`

Читает данные из Mongo. Разбор ответа воркера — в `lib/report-view.ts`: воркер
пишет питоновские имена полей, и превращение их в модель экрана держится в одном
месте, иначе следующий экран разберёт тот же отчёт чуть иначе.

Сквозное правило разбора: недостающее поле даёт `null` и рисуется прочерком.
Ноль на экране — это утверждение «измерено, вышло ноль».

Порядок блоков отвечает порядку вопросов: «сколько?» → «почему?» → «кто именно
так сказал?».

1. `HypothesisNotice` — материал это прогноз, а не измерение. Не украшение:
   отчёт без этой строки читают как результат опроса живых людей.
2. Пять `StatCard`: общее впечатление, NPS, «досмотрят до конца», «досмотрено, %»,
   эмоциональный индекс. Третья и четвёртая — разные величины и стоят рядом
   намеренно: первая считается по `retention_intent` (категориальному), вторая
   приходит из шкального вопроса анкеты и без него честно пуста.
3. Нарратив — абзацы синтеза. Каждый уже отфильтрован воркером: утверждение без
   таймкода или цитаты в отчёт не попадает.
4. `ScoreBar` по пяти критериям; при перекрытии > 1 на шкале затемнена зона
   разброса между повторами.
5. Топ-эмоции, точки риска прекращения просмотра с привязкой к таймкодам.
6. Посегментный срез: те же средние по группам аудитории. Показываются группы от
   `MIN_SEGMENT_PERSONAS = 5` персон — средняя по четверым выглядит на экране так
   же солидно, как средняя по сотне. Скрытые группы названы поимённо внизу
   секции: молча пропавшая группа читается как потерянные данные.
7. `PersonaAccordion` — карточки персон, первая страница грузится на сервере,
   остальные постранично.

Аккордеон получает разобранные карточки отчёта, а не персон из реестра. Персону
могли отредактировать или удалить после прогона, а отчёт обязан показывать ту
аудиторию, на которой посчитан. Ключ строки — персона **и** номер повтора: при
перекрытии ×3 ключ по одному `persona_id` схлопнул бы три карточки в одну.

Прежняя редакция этого файла отмечала здесь дефект: `if (!persona) return null`,
то есть молча исчезающая строка. Он снят вместе с переходом на карточки — искать
персону больше негде и нечему не находиться.

### Остальные экраны

`projects` (список, создание, карточка) · `personas` (реестр, карточка со всеми
атрибутами DNA) · `portraits` (витрина портретов из базы; редактор и
авто-дистилляция — на своих маршрутах) · `audience` (конструктор наборов —
дублирует шаг визарда, продуктовое решение открыто) · `surveys` (`SurveyBuilder`,
**шесть** типов вопросов — шестым добавлен `watched_share`) · `prompts`
(Промпт-студия: список, редактор, предпросмотр, активация версии) · `settings`
(настройки арендатора) · `api-docs` (Swagger UI, открыт без входа).

`runs/[id]/chat` — заглушка задачи #28. Экран говорит, чего пока нет, и
перечисляет два будущих режима. Раньше здесь стоял чат, работающий на вид:
переписка-затравка с таймкодами и функция отправки, возвращавшая одну
заготовленную строку на любой вопрос, ни к какому маршруту не обращаясь. Такой
экран хуже отсутствующего — по связному ответу с цитатами принимают решения.

### Четыре состояния каждого экрана

Загрузка → пусто → ошибка → данные. Три первых забывают потому, что при
разработке их не видно: у разработчика данные всегда есть. Экран, нарисованный
только для «данных», выглядит сломанным ровно тогда, когда пользователю тяжелее
всего — в первую секунду, на пустом аккаунте и при отказе базы.

Примитивы: `components/agora/States.tsx` — `Skeleton`, `SkeletonList`,
`SkeletonGrid`, `SkeletonHeader`, `EmptyState`, `ErrorState`. В одном файле, а не
по месту: пять экранов со своей пустотой дадут пять разных объяснений одного и
того же.

| Состояние | Механизм | Правило |
|---|---|---|
| Загрузка | `loading.tsx` рядом с `page.tsx` | skeleton по форме будущего контента, а не спиннер: место занято заранее, и приезд данных не двигает вёрстку |
| Пусто | `EmptyState` внутри страницы | что означает пустота и что сделать дальше, с кнопкой |
| Ошибка | `app/error.tsx` | причина текстом плюс `digest`; в production Next вырезает сообщение, и без digest пользователю нечего сообщить, кроме «не работает» |
| Нет объекта | `app/not-found.tsx` | «не существует или принадлежит другой команде» — ровно то, что означает 404 от обработчика |

`loading.tsx` заведены там, где экран ходит в базу: `/`, `/personas`,
`/portraits`, `/prompts`, `/runs/[id]`. Формы разные — список, сетка плашек,
блоки отчёта, — потому что скелетон, не совпадающий с содержимым, даёт тот же
скачок, что и спиннер.

## 5. Подключение backend

### Аутентификация

Auth.js v5, Credentials, стратегия **JWT** — провайдер Credentials не
поддерживает database-сессии. Плата: отзыв членства не действует мгновенно,
поэтому `guard.ts` перечитывает роль из базы на каждом owner-действии, а не
верит токену.

`trustHost: true` — self-host за обратным прокси, домен задан в `AUTH_URL`.

Вход из тестов и внешних клиентов идёт как в браузере: `GET /api/auth/csrf`,
затем `POST /api/auth/callback/credentials` с полем `csrfToken`. Сократить
нельзя — без куки колбэк вернёт 302 на форму логина, и это будет выглядеть
успехом.

### Закрыто по умолчанию

```ts
// lib/server/auth.config.ts
export const PUBLIC_PATHS = ["/login", "/api/auth", "/api/health", "/api-docs"];
```

Middleware пропускает без сессии только это, сопоставление — по префиксу. Новый
маршрут защищён сам собой. Обратный порядок — перечислять то, что надо
защитить, — означал бы, что забытый маршрут открыт, а забывают именно в эту
сторону.

Поэтому документация живёт в собственном сегменте `/api-docs`, а не внутри
`/api`: одна запись `"/api"` сняла бы защиту со всего дерева маршрутов.

### Скелет любого обработчика

```ts
import { requireSession, toResponse } from "@/lib/server/guard";
import { withTenant } from "@/lib/server/db";

export const dynamic = "force-dynamic";
export const runtime = "nodejs";

export async function GET() {
  try {
    const { tenantId, userId } = await requireSession();   // 401 сам
    return await withTenant(tenantId, async (client) => {  // RLS сам
      const { rows } = await client.query("SELECT … FROM projects");
      return Response.json(rows);
    });
  } catch (error) {
    return toResponse(error);                              // HttpError → ответ
  }
}
```

`requireSession()` — 401, `requireOwner()` — 403 с перечиткой роли,
`toResponse()` — единая форма ошибки. Разбираться с сессией в каждом
обработчике по-своему значит получить первое же расхождение как дыру.

### Изоляция в Mongo

RLS там нет. Правило жёстче: `tenant_id` берётся из сессии и **никогда** не
приходит аргументом функции.

```ts
// хорошо
export async function loadReport(session: SessionUser, taskId: string) { … }
// плохо: вызывающий подставит чужой
export async function loadReport(tenantId: string, taskId: string) { … }
```

### Запуск исследования

`POST /api/tasks` создаёт прогон и кладёт задачу в очередь. Идемпотентен по
параметрам вместе с seed: повторный вызов возвращает **200**, а не 201, и флаг
`created: false` — создано ведь не было.

В момент запуска пиннится **снимок промптов**: прогон идёт по тем версиям,
которые были активны на старте. Правка в Промпт-студии между двумя прогонами не
меняет результат задним числом.

### Прогресс

`GET /api/tasks/{id}/progress` — `text/event-stream`. Снимок, затем поток. См. §4.

### Отчёт

Два маршрута, и разделение продиктовано замером, а не вкусом:

| | агрегат + синтез | + карточки персон |
|---|---|---|
| 100 персон × 1 | 1,2 КБ | 132 КБ |
| 500 персон × 1 | 1,2 КБ | 654 КБ |
| 500 персон × 3 | 178 КБ | **2,1 МБ** |

`GET /api/tasks/{id}/report` — агрегат, нарратив, темы, точки риска, дисклеймер,
`audienceSize`. Читается целиком при открытии экрана.

`GET /api/tasks/{id}/report/personas?limit=&skip=` — карточки страницами,
`limit` до 200, в ответе всегда `total`. Аккордеон подтягивает их по мере
раскрытия. Одним документом 2,1 МБ поместились бы в Mongo (лимит 16 МБ), но
первый экран тянул бы два мегабайта ради пяти чисел в шапке.

**404, а не 403, на чужой прогон.** Фильтр по арендатору стоит в самом запросе,
поэтому чужой отчёт не находится. 403 подтвердил бы, что прогон с таким
идентификатором существует.

Форма ответа — `snake_case` из воркера (`aggregate.core_scores_mean`,
`retention_risk_points`), интерфейсные типы в `agora-types.ts` — `camelCase`.
Адаптер нужен, и он же место, где видно, каких полей не хватает.

### Загрузка видео

`POST /api/upload/presign` → браузер грузит в S3 напрямую → `POST
/api/upload/complete`. Файл через веб-сервер не идёт.

## 6. Переменные окружения

Контракт — `apps/web/.env.example`. Существенное для интерфейса:

```bash
DATABASE_URL=postgresql://agora_login:…@host:5432/agora   # НЕ суперпользователь
MONGODB_URL=mongodb://…                                    # + MONGO_DB
VALKEY_URL=redis://host:6379/0
AUTH_SECRET=…            AUTH_URL=http://localhost:3000    APP_URL=…
S3_ENDPOINT= S3_BUCKET= S3_ACCESS_KEY= S3_SECRET_KEY=
OPENAI_API_KEY= OPENAI_BASE_URL= AI_MODEL= VLM_MODEL=
```

Приложение подключается ролью `agora_login`, а не суперпользователем: RLS не
действует на суперпользователя, и под ним изоляции арендаторов нет вообще.
`agora_login` объявлен `NOINHERIT` намеренно — забытый `SET LOCAL ROLE agora_app`
падает с «permission denied», а не работает тихо.

**`pg` игнорирует поле `ssl`, если задан `connectionString`.** Путь к
сертификату передаётся параметром `sslrootcert` внутри самой строки.

## 7. Порядок сборки с нуля

1. Скелет `create-next-app` (TypeScript, Tailwind, App Router, **без** `--src-dir`),
   подключение к npm workspaces монорепо.
2. `globals.css` с `@theme`, `layout.tsx` с тёмной темой, `AppShell` + `NavBar`.
3. shadcn-примитивы в `components/ui/`.
4. `lib/server/db.ts` с `withTenant`, `guard.ts`, `auth.config.ts` + middleware.
   **До экранов**: закрытость по умолчанию проще заложить, чем добавить.
5. `login` и первый защищённый экран — проверить, что незалогиненный получает
   редирект, а `/api/health` открыт.
6. `projects`, `personas`, `surveys`, `settings` — обычные CRUD-экраны, на них
   отрабатываются четыре состояния и адаптеры к API.
7. Визард `studies/new` + xstate + черновики в Mongo.
8. `POST /api/tasks` и очередь Valkey.
9. Экран прогресса на SSE.
10. Экран отчёта: сначала адаптер `snake_case → camelCase` и загрузка из
    `/api/tasks/{id}/report`, потом аккордеон с пагинацией.
11. Промпт-студия и `/api-docs`.

Пункты 4 и 10 — те, где переделка дороже всего: первый потому, что дописать
защиту к готовым экранам труднее, чем заложить; второй потому, что форма отчёта
задаёт форму половины компонентов.

## 9. Ошибки, которые здесь уже делали

| Ошибка | Как проявляется | Защита |
|---|---|---|
| Нативный npm-модуль | собранный на Linux ломает запуск на macOS у соседа | только WASM (`hash-wasm`) |
| Запрос к Mongo без `tenant_id` | чужие данные; RLS там нет | `tenant_id` только из сессии, не аргументом |
| `tailwind.config.js` для токенов | тема перестаёт переключаться в рантайме | `@theme` в CSS (v4) |
| Polling вместо SSE | задержка и нагрузка; на длинной транскрипции ещё и таймаут прокси | SSE + `: ping` каждые 20 с |
| SSE без снимка вначале | вкладка, открытая в середине прогона, показывает пустоту | снимок, затем подписка |
| Перечислять защищаемые пути | забытый маршрут открыт | закрыто по умолчанию, `PUBLIC_PATHS` |
| `"/api"` в публичных путях | префиксное сопоставление открывает всё дерево | отдельный сегмент `/api-docs` |
| Пересчёт метрик на экране | число на экране расходится с отчётом | считает воркер, интерфейс отображает |
| Два списка узлов конвейера | шкала прогресса показывает не тот этап | общий `nodes.json` |
| Молчаливый `return null` в списке | строки исчезают, счёт не сходится | рисовать деградированную карточку |
| Экран нарисован только для «данных» | пустой аккаунт и отказ базы выглядят как поломка | `loading.tsx`, `EmptyState`, `error.tsx` — см. §4 |
| Работающий на вид экран на заготовках | ответ с цитатами относится к выдуманному прогону, и узнать это неоткуда | заглушка, честно называющая, чего нет |

Общее у большинства: **ошибка, которая проявляется поздно, дороже той, что
ломает сборку.**
