# AGORA — PRD FINAL (единый источник правды)

**Дата:** 23.07.2026 · **Ревизия:** 27.07.2026 · **Статус:** консолидирует PRD v1.0–v1.4 +
все решения интервью + пять фич, заказанных после интервью (§20).
**Заменяет** предыдущие версии как основной документ. Операционные артефакты (петля,
верификатор, промпты, граф задач) — отдельно (см. §19).

## 1. Executive Summary
Оценить сериал/ролик до релиза сегодня дорого и медленно (офлайн фокус-группа — недели и
десятки тысяч рублей за один показ в одном городе). **AGORA** генерирует синтетическую
аудиторию из AI-персон (цифровых двойников зрителей) по соцдем-параметрам, «показывает» им
видео и за минуты выдаёт аналитический отчёт — усреднённо по аудитории и по каждой персоне.
Отличие от «спросить у LLM»: (1) заземление на реальный grounding-корпус фокус-групп
(165 карточек респондентов), (2) реальный анализ видео (транскрипт+диаризация+разбор сцен),
(3) калибровка оценок по реальным распределениям, (4) изоляция ответов + QA-верификация,
(5) периметр РФ / self-host. ЦА — студии, онлайн-кинотеатры, продюсерские центры; MVP —
команды ≤10, мультиарендно. Позиционирование: **«прогноз, а не догадка»**.

## 2. Цели
**Бизнес:** ×кратно дешевле офлайн-группы; time-to-insight недели→часы; платящие пилоты
студий; expansion через переиспользование персон/портретов.
**Пользователь:** сигнал «зайдёт/не зайдёт» и *почему* до релиза; посегментные и по-персонные
инсайты со ссылками на сцены; итерация контента; сопоставимость между роликами на одной
аудитории.
**Не-цели:** замена реального исследования спроса; биометрия/RL-модели (Phase-2+); публичное
SaaS/биллинг на MVP; YouTube без скачивания; статистическая репрезентативность.

## 4. User Stories
- **Продюсер/шоураннер:** хочу за час сводный балл и разбор по сегментам, чтобы решить go/no-go до релиза.
- **Сценарист/режиссёр:** хочу видеть проседающие сцены и почему (цитаты+таймкоды), чтобы точечно переработать.
- **Маркетинг-аналитик:** хочу посегментные метрики (NPS, ретеншн, эмоции) для позиционирования.
- **Research lead:** хочу настраивать аудиторию/анкету/промпты и доверять заземлению.
- **Исследователь:** хочу переиспользовать набор персон на новом ролике для сопоставимости.
- **Владелец команды:** хочу изоляцию данных студии от других арендаторов.

## 5. Функциональные требования (P0/P1/P2 по impact)
**A. Аудитория и персоны.** P0 генерация по критериям (пол/возраст 6гр/гео 3/образование)
+ размер; P0 **карточка персоны + раздел «Персоны»** (плашки с датой → карточка: имя,
должность, местонахождение, поколение, род занятий, карьерный опыт, хобби + Big Five 1–5);
P1 реестр и переиспользование `persona_set` (преселект «Создать/Выбрать существующую»).
**B. Контент.** P0 загрузка mp4/mov/avi ≤700 МБ + выбор режима (короткое/длинное).
**C. Опрос.** P0 5 критериев 1–10; P1 конструктор (шкала/эмоции/удержание/рекомендация/открытый).
**D. Прогон.** P0 запуск (task_id) + **«Перекрытие»** + прогресс SSE; P0 обработка видео +
изолированная оценка; P1 QA (консистентность/галлюцинации/разнообразие).
**E. Отчёт.** P0 агрегат (5 критериев, NPS, ретеншн, эмоц.индекс, топ-эмоции) + аккордеон
по персонам; P1 **групповой синтез** (темы/согласие-несогласие/цитаты) + доверительные
границы (при replication>1) + дисклеймер «экспертная проверка»; P1 **«Поделиться»**
(публичная read-only ссылка с токеном, TTL и revoke — §20.2); P2 экспорт PDF.
**F. Знания/настройка.** P1 портреты аудиторий (.md-редактор + авто-дистилляция из датасета);
P1 Промпт-студия; P1 grounding-датасет (XLS+DOCX); P0 **Настройки** (кап стоимости/Whisper/
replication по умолчанию); P1 **файл доп. контекста об аудитории** на шаге генерации
персон (§20.4).
**G. Мультиарендность.** P0 RLS-изоляция, команды/пользователи/роли.
**H. Диалог и итерация (после первого green-гейта).** P1 **чат по результатам** в двух
режимах — аналитик по всему исследованию и допрос конкретной персоны (§20.1);
P1 **перезапуск с той же аудиторией и новыми вопросами** (§20.3).

## 6. User Experience
**Точки входа:** внутренний инструмент студии по приглашению; демо-прогон на коротком ролике.
**FTUE:** создание/вступление в команду → тур из 3 шагов (выбрать/сгенерировать аудиторию →
загрузить короткое видео → запустить → отчёт); пресеты + базовая анкета снижают порог.
**Core:** визард 7 шагов; левое меню — Проекты, **Персоны**, Портреты аудиторий, Промпт-студия,
Настройки. Раздел «Персоны»: сетка плашек → карточка (атрибуты §5.A + Big Five 1–5
визуализировано). Отчёт: агрегат+графики сверху, аккордеон по персонам снизу.
**Advanced:** переиспользование персон; авто-дистилляция портретов; Промпт-студия с версиями и
dry-run; посегментные срезы; экспорт; параметр «Перекрытие».
**UI/UX:** тёмная тема; прогрессивное раскрытие; честная маркировка «гипотезы»; живой прогресс;
заземляющие ссылки (таймкоды) в каждом обосновании.

## 7. Архитектура
**Frontend (TS):** Next.js App Router — UI, XState-визард, API-шлюз, отчёт, Промпт-студия,
Настройки, редактор портретов, Auth.js.
**Backend/ингест (Python):** FastAPI + **Celery** + **LangGraph**; ffmpeg, faster-whisper
large-v3, pyannote 3.1.
**Модели:** **Qwen 3.6** (мультимодальная) через OpenAI-совместимый **API timeweb.cloud** —
VLM-разбор кадров и рассуждение персон; Whisper+pyannote self-host на CPU. Абстракция
провайдера (`lib/ai-server.ts`, baseURL из env).
**Хранилища:** PostgreSQL+RLS; MongoDB; **Valkey** (очередь/прогресс/кэш); **S3 TimeWeb**
(медиа). Docker Compose. **TypeDB не используется** (графовая БД, не вектор; сходство — вектор
Phase-2). Общий контракт TS↔Python — canonical JSON Schema.

## 8. Бэкенд-пайплайн (LangGraph, внутри Celery-задачи)
State: `task_id, tenant_id, mode, video_ref, audio_ref, segments[], transcript_diarized,
chunk_analyses_ref, video_understanding, persona_ids[], survey, replication_count,
persona_answers[], qa_flags[], report, status, progress`.
```
extract_audio → [WhisperX ∥ pyannote(полный трек)] → merge_transcript
 → route(short|long) → sample_frames(PySceneDetect + fallback-интервал, панели×4)
 → analyze_chunks(Qwen VLM → JSON сцены, MAP через Send)
 → stitch(REDUCE: video_understanding по таймлайну, транскрипт=позвоночник)
 → evaluate_personas(Qwen, MAP, изоляция; каждая персона ×replication_count; пачки по 5)
 → qa(LLM-as-judge ×2: consistency/grounding/diversity)
 → analytics(агрегат + групповой синтез + доверительные границы + нарратив)
 → REPORT_READY (+FAILED, чекпоинтер, прогресс в Valkey → SSE)
```
Диаризация: pyannote по **полному** треку (глобально консистентные спикеры), слияние с
транскриптом по overlap. Длинное видео: сегменты ~10 мин, параллельная транскрипция+VLM,
глобальные таймкоды, склейка. Кэш разбора кадров. Изоляция персон — структурная (в срезе
state только своя DNA + video_understanding + survey).

## 9. Persona DNA + карточка + раздел «Персоны»
**DNA — 8 категорий** (Big Five 1–5; ~40–60 полей MVP → 120):
1. Демография (8–10); 2. Big Five 1–5; 3. Ценности/убеждения (5–8, ВЦИОМ+соц.приоритеты+
культ.взгляд+философия+отношение к будущему); 4. **Зрительское поведение** (8+: жанры,
толерантность к насилию/темпу/длине, лояльность к франшизам/актёрам, влияние рекомендаций,
реакция на идеолог./рекл. посылы, ожидания от продакшена, attention span); 5. Стиль общения
(5–6); 6. Принятие решений (5–6: риск/обдуманность/влияние сверстников/доверие авторитету);
7. Использование технологий (4–5); 8. Интересы/образ жизни (5+). + narrative + seed.
Guardrail: ответ ограничен задокументированным профилем.
**Карточка персоны — полный профиль, не подмножество.** Клик по плашке открывает карточку,
показывающую **все** атрибуты персоны: шапка (имя, должность, местонахождение, поколение,
род занятий, карьерный опыт, хобби) + все 8 категорий DNA с подписанными полями (Big Five
визуализировано) + narrative + seed. В контексте конкретного исследования карточка
дополнительно показывает ответы этой персоны, её цитаты с таймкодами и кнопку «Спросить
персону» (§20.1). Приёмка: ни одно непустое поле canonical JSON Schema не теряется
при рендере. **Раздел «Персоны»** в левом меню: сетка плашек (имя, поколение, род занятий,
дата) → карточка.

## 10. Данные и grounding-корпус
**Postgres (RLS по tenant_id):** teams, users, projects, personas, persona_sets,
audience_portraits, prompts, surveys, tasks(+prompts_snapshot,+replication_count), reports,
settings. **MongoDB:** chunk_analyses, persona_answers, wizard_drafts, grounding_dataset.
**S3:** video/audio/frames по task_id.
**Grounding-корпус (`data/grounding/unified_respondent_sessions.json`,
165 записей — файл на месте, поля сверены с верификатором):**
профильная карточка респондента из 8 секций (content_under_test, experiment_metadata,
socio_demographics, psychographics_and_values, agora_core_scores_1_to_10,
perception_and_retention, qualitative_verbatims, focus_group_verbatims, all_survey_responses).
Собран из XLS-анкет + DOCX-стенограмм 4 сериалов (Константинополь/Ландыши/Сестра/Тюремный
дневник), сегменты по (сериал×город). Наполнение 100% (пол, cinematography, сегмент,
focus_group_verbatims).
**Фактические реперы (замерено 27.07.2026, это цели калибровки):** средние баллы —
overall_impression 7.34 · plot 7.58 · acting 8.12 · music 8.07 · cinematography 8.00.
Распределения — возраст: 35-44 41% / 25-34 26% / 45-59 17% / 18-24 11% / 60+ 3% / 14-17 2%;
гео: центры субъектов 55% / столицы 45%; пол: жен 67% / муж 33%.
⚠️ **Известное ограничение заземления:** третья гео-группа «иные НП» представлена **0 из 165**
записей. Аудитория с этой группой генерируется без корпусного заземления — UI обязан
предупреждать об этом, а выводы по ней помечать пониженной уверенностью.
**Методология генерации персон из корпуса:** (1) распределения по (сериал×город×сегмент) —
сэмплирование по реальным долям, не равномерно; (2) калибровка баллов по реальным средним
(overall~7.3, plot~7.6, acting~8.1, music~8.1, cinematography~8; разброс 2–9) ±приоры;
(3) стилевое+аргументативное заземление на verbatims (против sycophancy); (4) ценности ВЦИОМ→
DNA; (5) сегмент-ориентированная установка к контенту; (6) представитель сегмента, не копия.

## 10-бис. Чат-агент по результатам (архитектурная позиция)
Чат (§20.1) — **отдельный синхронный агент, а не оркестратор.** Оркестратор — это
LangGraph-поток внутри Celery-задачи: он эфемерен, завершается вместе с прогоном и не
хранит диалог. Чат живёт поверх *завершённого* `task_id` и имеет read-only доступ к его
артефактам: `report`, `persona_answers`, `video_understanding` (с таймкодами), `survey`,
`qa_flags`. Данные ограничены (20–60 персон × ответы + отчёт), поэтому на MVP хватает
подачи в контекст без RAG; вектор — Phase-2 вместе с §7. Треды — в Postgres
(`chat_threads`/`chat_messages`, RLS по `tenant_id`).

## 11. Промпт-студия
Все промпты — в реестре `prompts` (key, stage, template с `{{плейсхолдерами}}`, variables,
model_params, version, is_active, is_default), редактируются в меню. UI: список по стадиям,
редактор с валидацией переменных, preview/dry-run, версии, restore default. Резолв: активная
версия арендатора → дефолт. **Пиннинг версий на task** (`prompts_snapshot`) для
воспроизводимости. Seed-промпты (**13**) готовы в `prompts/`: 11 исходных +
`chat.analyst` и `chat.persona_followup` под §20.1.

## 12. Настройки (per-tenant)
Кап стоимости вызовов Qwen (дефолт «авто»/жёсткий кап); выбор Whisper large-v3/turbo;
дефолт `replication_count`; конфиг провайдера (baseURL из env). Хранение tenant-scoped.

## 13. Метрики успеха
**Пользователь:** adoption, прогонов/неделю, time-to-report, CSAT, доля с переиспользованием.
**Бизнес:** экономия vs офлайн, конверсия пилот→подписка, retention/expansion, платящие студии.
**Технические (пороги /goal):** аптайм; success-rate пайплайна; grounding-точность;
изоляция+RLS 100%; 0 секретов; субъективное качество персон/отчёта ≥7/10 (blind).

**Как считается grounding-точность (уточнено 27.07.2026).** Порог |распределения−реальные|
≤ 0.10 по age_group/geo/gender проверяется **только на эталонном (reference) конфиге
генерации** — «сгенерируй аудиторию как в корпусе», без пользовательских фильтров.
Пользовательские прогоны с произвольным составом («дай мне только 18-24») от этой проверки
освобождены: иначе продуктовый сценарий выбора аудитории противоречил бы порогу.
Калибровка баллов |средние−реальные| ≤ 1.0 по каждому из 5 критериев действует **всегда**,
включая пользовательские прогоны и прогоны с приложенным файлом контекста (§20.4) — именно
она держит «прогноз, а не догадку».

## 14. Технические соображения
Интеграции: видео (файл/CDN); модели в периметре РФ через абстракцию провайдера; S3;
существующий фронт. Данные/безопасность: мультиарендная RLS-изоляция; резидентность РФ;
секреты из env; grounding-корпус — обезличивание, генерация представителей, а не копий;
retention медиа. Масштабируемость: очередь/fan-out; map-reduce для длинных; горизонтальные
воркеры; кэш чанков; резюмируемость.

## 15. Инфраструктура и деплой (TimeWeb)
Frontend Next.js (Node 24) + Backend FastAPI/Celery (Python 3.14), **Docker Compose на VPS**.
Managed БД: **PostgreSQL 18 + MongoDB 8.0 + Valkey 9.1**. **S3 100 ГБ Standard**.
VPS CPU-only (модели по API): **8 vCPU / 16 ГБ RAM / 100 ГБ NVMe**, GPU не нужен.
⚠️ Whisper large-v3 CPU для длинных роликов медленный — параллельные сегменты; turbo как
fallback. Новый репозиторий — с чистой истории (утёкшие ключи перевыпустить).

## 16. Вехи и последовательность
Ф0 Фундамент (инфра, БД+RLS, Auth, Промпт-студия, Настройки, DNA) → верификатор запускается.
Ф1 Срез короткого видео end-to-end → **e2e_short green**.
Ф2 Длинное видео (map-reduce) → e2e_long green.
Ф3 Знания (датасет XLS+DOCX, портреты+авто-дистилляция).
Ф4 Фичи после гейта + полировка: чат по результатам, «Поделиться», перезапуск с новыми
вопросами, файл контекста аудитории, отчёт/экспорт, онбординг → MVP для пилотов.
Ф5 post-MVP: вектор/RAG, непрерывная калибровка, AI-модератор дискуссии.
Точка входа — **граф из 31 задачи** по зависимостям (`evals/state/tasks.json`).

## 17. Guiding Principles
Фокус на пользователе (go/no-go и посценная обратная связь важнее технологии); ясность и
точность (явные сущности/потоки); выравнивание по SMART-целям; комплексная детализация и
edge cases (пустой контент, длинные видео, дыры в данных, галлюцинации, mode collapse, сбои
моделей); кросс-функциональность (исследователь/инженер/студия); гибкость и масштабируемость
(абстракция провайдера, очередь, map-reduce, вектор Phase-2).

вслепую, либо три недели и очные группы в пяти городах. Сейчас она грузит серию в AGORA,
берёт сохранённый набор из 40 персон, добавляет пару вопросов, ставит «Перекрытие 3» и жмёт
«Запустить». Через 20 минут — отчёт: общее 7.2, но сегмент 45+ проседает на сцене насилия в
3-м акте; персона «Полина, 33» пишет: «на 14-й минуте перестала верить». Марина перемонтирует
сцену, гонит на той же аудитории — 7.9. На защите — не интуиция, а сопоставимые цифры и
конкретные правки. «В производство».

## 20. Фичи ревизии 27.07.2026
Все четыре — **после** первого green-гейта `e2e_short` (в графе `blockedBy: [22, …]`):

### 20.1 Чат по результатам исследования (задача #28)
На экране результатов завершённого `task_id` — диалог в двух режимах.
**«Аналитик»** — вопросы по всему исследованию («почему сегмент 45+ просел?», «какие сцены
теряют внимание?»). Отвечает только по артефактам задачи, каждый тезис — со ссылкой на
таймкод или именную цитату; нет данных → честное «в этом исследовании не измерялось»,
без правдоподобных достроек; факт и интерпретация разделены явно (промпт `chat.analyst`).
**«Спросить персону»** — допрос конкретной персоны из её карточки, как респондента после
фокус-группы. В контекст подаётся **только** её DNA + video_understanding + survey + её
собственные прежние ответы: та же структурная изоляция, что в основном пайплайне — персона
не знает ни других персон, ни того, что участвует в исследовании. Guardrail «ответ ограничен
профилем» действует: вне профиля → «не знаю», а не выдумка. Отслеживаются флаги
`out_of_profile` и `contradicts_previous` (промпт `chat.persona_followup`).
Архитектура — §10-бис. Стоимость: каждое сообщение — платный вызов, учитывается в капе (§12).

### 20.2 «Поделиться» результатом (задача #29)
Кнопка на экране отчёта создаёт **публичную read-only ссылку**: криптостойкий токен
≥128 бит, настраиваемый TTL, кнопка «Отозвать», список активных ссылок, аудит-лог просмотров.
Это **единственный санкционированный обход RLS** в системе — реализуется отдельной политикой
на таблице `report_shares` и обязан быть покрыт негативными тестами: истёкший токен → 410,
отозванный → 410, чужой/подобранный → 404, через публичную страницу недоступны другие
отчёты, другие арендаторы, чат и любые мутации. Публикуется полный отчёт; скрытие
поимённых персон — опция шеринга.

### 20.3 Перезапуск с той же аудиторией и новыми вопросами (задача #30)
«Перезапустить с этой аудиторией» на экране результатов. Переиспользуются `persona_set`
**и разбор видео родительской задачи** — VLM не пересчитывается (главная экономия, самая
дорогая стадия). Анкета дополняется новыми вопросами. Память персон — **выбор пользователя,
оба режима обязательны:**
- **«Допрос»** — персона получает свои прежние ответы и отвечает только на новые вопросы.
  Дёшево, непротиворечиво, старые баллы не двигаются; отчёт дополняется.
- **«Чистый прогон»** — вся анкета (старая + новая) задаётся заново в изоляции.
  Статистически чище, но прежние баллы могут поехать, и это дороже.

UI обязан объяснять последствия каждого режима для сопоставимости — это методологический
выбор пользователя, а не техническая деталь. Связь прогонов — `tasks.parent_task_id`.

### 20.4 Файл доп. контекста для генерации аудитории (задача #31)
На шаге «Аудитория» пользователь может приложить файл с дополнительным контекстом о
зрителях (pdf/docx/md/txt/xls). Файл **не создаёт нового механизма**: он дистиллируется в
«портрет аудитории» существующим промптом `portrait.distill` и подаётся в `persona.generate`
дополнительной секцией.
**Принцип приоритета — корпус выше файла.** Файл *уточняет* персон (контекст ниши, лексика,
специфика продукта), но **не переопределяет** распределения по соцдему и калибровку баллов
из grounding-корпуса. Иначе продукт скатывается обратно в «спросить у LLM» и теряет своё
единственное содержательное отличие. Конфликт разрешается в пользу корпуса и показывается
пользователю предупреждением. Приёмка: с приложенным файлом эталонный `persona_grounding`
остаётся green (§13).
