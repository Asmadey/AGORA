**Главное содержание этапа В — корень отбраковок по `grounding`.** Панель из четырёх
кадров уходила в модель одной картинкой, модель возвращала ОДНО описание, а таймкод ему
ставился от ПЕРВОГО кадра панели. Кадры при этом брались подряд по всему ролику, поэтому
в одну панель попадали моменты, разнесённые на полминуты: на ролике 2:42 вышло 6 описаний
вместо двух десятков. Персона, сославшаяся на середину, получала описание от начала, и
судья справедливо видел несовпадение.

Теперь панель — это сцена: склейки ищет детектор, граница ближе 2 с считается дребезгом
и приклеивается к предыдущей сцене, отрезок длиннее 30 с режется на равные блоки. Кадры
берутся ВНУТРИ сцены, у описания есть начало и конец. Число вызовов модели не выросло.

**Найдено и починено попутно** (каждое — вида «написано, но не работает»):

- снимок промптов не применялся к `respondent.system` и `respondent.user`: Промпт-студия
  на опрос персон не влияла вовсе, а отчёт ссылался на версию, по которой прогон не шёл;
- кэш VLM не передавался в разбор — повтор прогона платил заново; поле ключа писалось как
  `cache_key` при индексе на `content_hash`;
- жёсткий кап вызовов жил в интерфейсе и в `CallBudget.for_task`, а снимка настроек в
  задаче не существовало: ограничения не было никогда;
- анкета могла не доехать до персоны молча — подстановка идёт строкой, и без метки
  `{{survey_questions}}` прогон проходит целиком, а персоны придумывают вопросы сами;
- `tasks.progress` заведена с первого дня и не писалась никем;
- кадры и content pack жили в несмонтированном `/tmp` и умирали с контейнером;
- `dataset_sha256()` не вызывалась нигде.

**Чего в этапах нет и почему:**

- метрик заземления в разделе «Корпус» (охват по возрасту/гео/полу, отклонение выдачи).
  Считать по загруженной странице нельзя, а запрос с агрегатами не написан;
- перегенерации забракованных ответов. Её нет в системе вовсе: ответ исключается из
  агрегата и не переспрашивается. Панель QA называет это своими словами.

**Что НЕ проверено.** Всё выше — статический и модульный уровень: 288 тестов воркера,
`ruff`, `tsc`, `eslint`, `next build`, 26 тестов `node:test`, CDD-тесты задач. Прогон в
среде пользователя не выполнялся. Главный критерий этапа В — golden-сет `--repeat 3` —
остаётся непроверенным, и по этой причине #16/#17 не переведены в `done`.

**Что нужно от владельца, чтобы проверить:** применить миграции 16–18 (`migrate.sh`),
пересобрать образ воркера, засеять корпус
(`node apps/web/scripts/seed-corpus.mjs --team-id <uuid>`), перевыпустить
`OPENAI_API_KEY` — прежний побывал в переписке (§6-бис).

### Как повторить прогон

```bash
# на сервере, из /root/AGORA
set -a; . ./.env.local; set +a
export BASE_URL=https://agora.185-154-194-125.sslip.io
export DATABASE_URL="${DATABASE_URL/@postgres:/@127.0.0.1:}"   # имя docker-сети с хоста не резолвится
for f in evals/tests/test_task*.py; do python3 "$f" >/dev/null || echo "FAIL $f"; done
```

Тесты воркера (#13, #15, #16, #18, #19, #20) так гонять **нельзя** — их зависимости живут
в контейнере, и на python хоста они дают `ModuleNotFoundError`, неотличимый от дефекта
кода. Для них — разовый контейнер из образа воркера:

```bash
docker run --rm --network agora_default --env-file /root/.env.clean \
  -v /root/AGORA:/repo -w /repo agora-worker python evals/tests/test_task19_qa.py
```

`.env.clean` — копия `.env.local` со снятыми кавычками: `docker run --env-file` их не
снимает, в отличие от `docker compose`, и `WHISPER_COMPUTE_TYPE` приезжает как `"int8"`.
