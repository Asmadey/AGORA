## Как читать

| Колонка | Значение |
|---|---|
| **Кто** | 🤖 — выполняю я, результат прикладываю в PR / loop-state. 👤 — выполняет Влад в своей среде (VPS, браузер, живая модель). 🤝 — обе стороны: я готовлю команду и фикстуру, Влад запускает. |
| **Статус** | ✅ пройден · 🟡 частично · ⬜ не выполнялся · 🚫 заблокирован незаконченной задачей |

**Правило честного результата.** Если проверка не может выполниться (нет ключа,
нет базы, нет модели) — она пишет SKIP и называет причину. Тест, который в
отсутствие среды выдаёт «пройдено», хуже отсутствующего теста: он гасит
подозрение вместо того, чтобы его вызывать.

## 1. Медиа-препроцессинг (задача #14)

Смысл блока: **все таймкоды в системе — таймкоды прокси-файла** (Decision Log
#14). Если прокси и исходник разошлись по длительности, разъедется всё, что
дальше: транскрипт, сцены, ссылки в отчёте.

### TC-1.1 — ffprobe читает реальный контейнер 🤖 ✅

```bash
cd services/agent-core && python3 -c "
from agent_core.media.probe import probe
i = probe('../../docs/video/15 min.mp4')
print(i)
"
```

**Ожидается:** `duration_sec` ≈ 917, ненулевые `width`/`height`, `fps` > 0,
`has_audio = True`. **Провал, если** длительность взята из метаданных
контейнера и расходится с реальной дорожкой больше чем на 1 с.

**Факт:** 917.0 с, аудиодорожка найдена.

### TC-1.2 — прокси: 5 fps, ширина 640, звук отброшен 🤖 ✅

```bash
python3 -c "
from agent_core.media.proxy import make_proxy
from agent_core.media.probe import probe
make_proxy('../../docs/video/15 min.mp4', '/tmp/proxy.mp4')
print(probe('/tmp/proxy.mp4'))
"
```

**Ожидается:** длительность прокси совпадает с исходником с точностью до кадра;
`has_audio = False`.

**Почему звука в прокси нет и это правильно:** прокси нужен для сцен и кадров,
звук в нём — лишние мегабайты на каждом кадре анализа. Аудио берётся **из
исходника**, а не из прокси. Это уже стоило одного ложного бага: вызов
`extract_audio(proxy)` падает с «в файле нет звуковой дорожки», и это ожидаемое
поведение, а не дефект.

**Факт:** 917.0 с, 5 fps, звука нет.

### TC-1.3 — извлечение аудиодорожки 🤖 ✅

```bash
python3 -c "
from agent_core.media.audio import extract_audio
from agent_core.media.probe import probe
extract_audio('../../docs/video/15 min.mp4', '/tmp/audio.wav')
" && ffprobe -v error -show_entries stream=sample_rate,channels,codec_name -of default=nw=1 /tmp/audio.wav
```

**Ожидается:** `codec_name=pcm_s16le`, `sample_rate=16000`, `channels=1`.
16 кГц моно — не произвольный выбор, а вход, которого ждут и Whisper, и Silero
VAD; на 44.1 кГц стерео VAD даёт другие границы, и таймкоды диаризации перестают
совпадать с таймкодами транскрипта.

**Провал, если:** частота отличается от 16000, или файл нулевой длины при
`has_audio = True` в TC-1.1.

**Факт:** 16 кГц, моно, 917 с.

### TC-1.4 — нарезка на фрагменты без потери суммарной длительности 🤖 ✅

```bash
python3 -c "
from agent_core.media.proxy import segment
from agent_core.media.probe import probe
parts = segment('/tmp/proxy.mp4', '/tmp/parts', seconds=600)
tot = 0
for p in parts:
    d = probe(p).duration_sec; tot += d; print(p.name, round(d,1))
print('сумма', round(tot,1))
"
```

**Ожидается:** 2 фрагмента, 614.6 + 302.4 = 917.0 — сумма равна длительности
прокси. Первый кусок длиннее 600 с законно: `ffmpeg -f segment` режет по
ключевым кадрам, а не по секундомеру.

**Провал, если** сумма меньше исходной длительности: значит хвост потерян, и
последние минуты ролика не попадут ни в транскрипт, ни в сцены. Это самый
опасный отказ в блоке, потому что внешне выглядит как успешный прогон.

**Факт:** 614.6 + 302.4 = 917.0. ✅

### TC-1.5 — понятный отказ на битом файле 🤝 ⬜

Подать на вход текстовый файл с расширением `.mp4`.
**Ожидается:** `MediaError` с текстом про формат, а не `IndexError` из разбора

## 2. Транскрипт и диаризация (задача #15)

### TC-2.1 — транскрипт 15-минутного ролика на large-v3 🤝 ⬜

```bash
WHISPER_MODEL=large-v3 WHISPER_COMPUTE_TYPE=int8 python3 -c "
from agent_core.asr.transcribe import transcribe
segs = transcribe('/tmp/audio.wav')
print(len(segs), 'сегментов')
for s in segs[:5]: print(round(s.start,1), round(s.end,1), s.text[:70])
print('последний конец:', round(segs[-1].end,1))
"
```

**Ожидается:**
- сегментов больше нуля, текст осмысленный и на языке ролика;
- таймкоды монотонны: `start[i+1] >= start[i]`;
- `segs[-1].end` не превышает 917.0 больше чем на 0.5 с.

**Провал, если** конец последнего сегмента заметно больше длительности — Whisper
на хвосте склонен «доезжать» за границу; в Content Pack такое подрезается
(TC-4.2), но на этом уровне расхождение надо увидеть.

**Отдельно проверить галлюцинации на тишине:** взять кусок без речи и убедиться,
что `vad=True` даёт пустой список, а не выдуманную фразу. Именно ради этого VAD
включён по умолчанию.

### TC-2.2 — large-v3 против medium по памяти 👤 ⬜

На VPS с 7.8 ГБ large-v3 уже падал по OOM, поэтому стоит `medium`. Замерить:

```bash
/usr/bin/time -v python3 -c "from agent_core.asr.transcribe import transcribe; transcribe('/tmp/audio.wav')" 2>&1 | grep Maximum
```

**Ожидается:** пиковая память под `int8` в районе 2–3 ГБ. **Если больше 6 ГБ** —
вывод не «уменьшить модель», а «инстанс меньше §15 PRD (8 vCPU / 16 ГБ)»; это
записано в блокеры отчёта.

### TC-2.3 — диаризация: границы совпадают с VAD 🤝 ⬜

```bash
python3 -c "
from agent_core.asr.transcribe import vad_segments
from agent_core.asr.diarize import diarize
spans = vad_segments('/tmp/audio.wav')
turns = diarize('/tmp/audio.wav', spans=spans)
print(len(spans),'участков речи;', len(turns),'реплик;', len({t.speaker for t in turns}),'спикеров')
"
```

**Ожидается:** число спикеров правдоподобно для ролика (не 1 на диалоге и не 20
на монологе); реплики лежат внутри участков VAD.
**Ожидаемый SKIP:** без `HF_TOKEN` для pyannote — `DiarizationUnavailable`.
Это законный исход, а не сбой: продукт обязан работать и без диаризации, просто
без ярлыков спикеров.

### TC-2.4 — один и тот же VAD у транскрипта и диаризации 🤖 ✅ (статически)

Проверяется CDD-тестом #15. Если границы разойдутся, спикер в Content Pack
будет приписан не той реплике — дефект, который в отчёте выглядит как
«персона неверно поняла героя».

## 3. Сцены, кадры и VLM-разбор (задача #16)

### TC-3.1 — детекция сцен на реальном ролике 🤝 ⬜

```bash
python3 -c "
from agent_core.frames.scenes import detect_scenes, keyframe_timestamps

print(len(sc), 'сцен'); print(keyframe_timestamps(sc)[:10])

```

**Ожидается:** число сцен соответствует монтажу (для 15-минутного ролика
десятки, не 2 и не 2000). Границы внутри `[0, 917]`.

**Ожидаемый фолбэк:** если PySceneDetect недоступен, модуль обязан вернуть
равномерную нарезку по интервалу, а не пустой список. Нулевые сцены → пустой
Content Pack → респонденты «смотрят» ничего.

### TC-3.2 — opencv стоит headless и импортируется 🤖 ✅

Решение: `libGL` **не ставится**. `opencv-python-headless` его не требует;
установка libGL замаскировала бы настоящую причину отказа — pip, тихо ставящий
GUI-сборку, — и притащила бы GTK/X11 в контейнер без экрана.

Вместо этого в `infra/worker.Dockerfile` стоит проверка на этапе сборки: если в
образе оказалась `opencv-python` (GUI) или не оказалось ни одной сборки, сборка
падает с внятным текстом.

```bash
docker compose build worker
```

**Ожидается:** сборка проходит; при подмене на GUI-сборку — падает на этом шаге,
а не в рантайме на первом видео.

### TC-3.3 — дедупликация кадров 🤝 ⬜

**Ожидается:** на статичном плане `dedupe` схлопывает почти одинаковые кадры
(порог Хэмминга 4), на динамичном — почти ничего не режет. Проверять именно на
двух разных кусках ролика: агрессивный порог выкидывает содержательные смены
плана, слабый — раздувает счёт VLM-вызовов.

### TC-3.4 — бюджет вызовов VLM не превышается 🤝 ⬜

**Ожидается:** при исчерпании `CallBudget` поднимается `CostCapExceeded`, и уже
разобранные панели не теряются. Проверить, что повторный запуск на том же ролике
берёт результат из кэша (`MongoCache`), а счётчик вызовов не растёт: ключ кэша
считается от изображения, шаблона промпта и имени модели — смена любого из трёх
обязана дать промах.

### TC-3.5 — таймкод проставлен каждой панели 🤝 ⬜

**Ожидается:** у каждого результата анализа есть `timestamp_sec` в границах
`[0, 917]`. Панель без таймкода бесполезна: отчёт не сможет сослаться на момент.

### TC-6.4 — разнообразие ответов на живой модели 🚫 ждёт ключа

```bash
python3 evals/check.py 2>&1 | grep response_diversity
```

**Ожидается:** `distinct_2 >= 0.55`, `score_stdev >= 1.0`, `mode_collapse = false`.

**Пороги предварительные и требуют калибровки.** Процедура записана рядом с
константами в `agent_core/respondent/diversity.py`: прогнать 20 персон на
реальном материале, посчитать значения, затем испортить промпт (убрать из
`respondent.system` пункт про право не понравиться) и посчитать снова; порог
ставится между полученными значениями, ближе к нижнему.

**Почему две метрики, а не одна:** distinct-2 меряет лексику и обманывается,
когда персоны разными словами говорят одно и то же; дисперсия баллов меряет
позицию и обманывается на случайных оценках, не связанных с текстом. Порознь
каждая зеленеет на бесполезном прогоне.

**Почему `temperature = 0.9`, а не 0:** при нулевой температуре метрика
разнообразия мерила бы нашу конфигурацию, а не поведение модели.
