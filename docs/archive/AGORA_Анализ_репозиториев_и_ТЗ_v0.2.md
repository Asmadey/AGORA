(та была догадкой по брифу и в ключевых местах ошибалась — например, считала, что

## 0. Главный вывод

Во всех трёх репозиториях реализован **НЕ** мультиагентный оркестрируемый пайплайн
из брифа, а **упрощённый MVP «симуляция одним-несколькими вызовами LLM»**. Это
рабочий прототип, но между ним и целевой архитектурой брифа — большая дистанция.
Ниже — что именно есть, чего нет, какой репозиторий брать за базу и что достраивать.

Модель везде — `gemini-3-flash-preview` (в двух Next-вариантах — через прокси
`api.timeweb.ai`, в `agora` — напрямую Gemini + опционально OpenAI-совместимые).

⚠️ **Безопасность — критично:** в коде захардкожены живые API-ключи (`lib/ai.ts`
строка 4 — ключ timeweb, отдаётся в браузер через `dangerouslyAllowBrowser: true`;
`agora/api/index.ts` строка 50 — фолбэк-ключ Gemini). Эти ключи нужно **отозвать и
перевыпустить**, и ни в коем случае не пушить в публичный репозиторий. Подробнее — §6.

## 2. Что реально реализовано (по факту, из кода)

**`agora` (Vite + Express)** — эндпоинты в `api/index.ts`:
- `POST /upload` и `/upload-url` — загрузка видео в Gemini Files API (100 МБ лимит),
  YouTube-ссылки трактуются как текст;
- `POST /audience/generate` — генерация агентов. Промпт жёстко просит **10** агентов,
  схема простая: `id, name, age, region, profession, personality, coreValue`;
- `POST /research/run` — **ОДИН большой вызов Gemini**, который сразу и «смотрит»
  видео, и симулирует всех агентов, и выдаёт весь отчёт: `agoraScore, nps,
  emotionalIndex, avgRetention, engagementData (5 эпизодов), emotions,
  valuesDistribution, narrative, vciomSummary` (методология ВЦИОМ) + `agentResponses`;
- `POST /research/chat` — чат с «фокус-группой» по готовому отчёту.
- UI: Dashboard, Audiences, Surveys, Settings, ProjectHub с вкладками
  Content / Audience / Survey / Run / Report.

**`Agora-latest` / `agora-12-main` (Next.js)** — `lib/ai.ts`:
- `generateAudience(size = 20)` — **по умолчанию 20 агентов** ✓. Профиль богаче:
  `gender, city, income, values[], personality, newsMemory, economicContext`;
- `simulateSurvey(agents, project, survey)` — **все агенты в одном вызове**;
- `generateReport(...)`, `chatWithAudience(...)`, плюс `fetchNewsContext()` и
  `generateNewsAnalysis()` — реакция аудитории на реальные новости;
- **Интерфейс `SurveyResponse` содержит ровно 5 критериев из брифа**:
  `overallScore, plotScore, actingScore, musicScore, cameraScore` (+ `nps, emotions,
  values, qualitativeFeedback`), а `Report.averageScores = {overall, plot, acting,
  music, camera}`. Это ближе всего к ТЗ по анкете;
- Видео: **не анализируется** — берётся только oEmbed-метаданные (`noembed.com`:
  title/author/платформа). Агенты «додумывают» содержание; в чате модель прямо
  инструктируется выдумывать таймкоды и сцены;
- Персистентность: `lib/db.ts` на **localforage** (IndexedDB в браузере) —
  сущности `Project, AudienceConfig, SurveyConfig, NewsReport`, типы вопросов:
  `rating, emotions, values, nps, open, matrix, slogan, retention`.

## 3. Разрыв «бриф ↔ реальность» (это и есть объём работы)

| Требование брифа | Что в коде сейчас | Действие |
|---|---|---|
| **Orchestrator** (раздаёт задачи, изолирует ответы) | нет; всё в 1–3 вызовах | построить |
| **Persona Generator + Persona DNA** (Big Five, 30+ параметров, нарратив) | профиль ~8–10 полей, без Big Five и нарратива | расширить схему и генератор |
| **Изоляция респондентов** (каждый отвечает независимо) | все агенты в одном промпте — не независимы | вызовы по одному агенту |
| **Respondent Agent** (симуляция просмотра + анкета) | есть (в общем вызове) | вынести в отдельного агента |
| **Content Processor** (транскрипт, деление на акты, описание сцен) | `agora` — нативный видео-анализ Gemini (без явных транскрипта/актов); Next — только метаданные | построить полноценный препроцессинг |
| **QA Agent** (консистентность ответов профилю) | нет нигде | построить |
| **Analytics Agent** (агрегация + нарративный отчёт) | есть (в общем вызове/`generateReport`) | вынести и усилить |
| **20 персон** | Next — 20 по умолчанию ✓; `agora` — 10 | стандартизировать 20 |
| **5 критериев 1–10** | Next — да (в модели данных) ✓; `agora` — свободная анкета | стандартизировать на 5 |
| Воспроизводимость (seed) | нет | добавить seed |
| Серверная персистентность | только клиент (localforage) / стейт | вынести на сервер (БД) |

Короткий вывод: **ядро агентов (Orchestrator, Persona DNA, изоляция, QA) нужно
строить заново**; генерацию/симуляцию/отчёт — рефакторить из имеющегося; лучший
видео-пайплайн уже есть в `agora`, лучшая модель анкеты — в `Agora-latest`.

## 4. ТЗ: стек и архитектура (пересмотрено под факты)

**Отказ от идеи v0.1 о Python/LangGraph.** Весь рабочий код — на TypeScript
(Vite+Express и Next.js), с Gemini и структурированным выводом (`responseSchema`).
Вводить Python — значит выбросить работающее. **Рекомендация: остаёмся в TypeScript
end-to-end** и эволюционируем существующее в настоящий пайплайн.

**Фреймворк — рекомендую консолидировать на Next.js (App Router)** как единый
каркас (оба AI-Studio-репо уже на нём; server actions / route handlers заменяют
Express). При этом **портировать из `agora` бэкенд нативного видео-анализа Gemini**
(логику `/upload` и видео-части `/research/run`) в route handlers.

Итоговый стек:
- **Frontend + сервер:** Next.js (App Router) + TypeScript + Tailwind + shadcn/Radix
  (уже используется во всех репо).
- **LLM-слой:** обёртка провайдер-агностик (Gemini напрямую для видео; опционально
  OpenAI-совместимые/timeweb для текста). Ключи — только в env, **не в коде**.
- **Структурированный вывод:** Gemini `responseSchema` (паттерн уже есть в
  `agora/api/index.ts`) + zod-валидация на TS-стороне.
- **Ядро агентов:** отдельные TS-модули (`orchestrator`, `personaGenerator`,
  `contentProcessor`, `respondent`, `qa`, `analytics`) с изоляцией и контролем
  конкурентности (p-limit / очередь) для 20 параллельных респондентов.
- **Обработка видео:** Gemini Files API (нативно, как в `agora`) для транскрипта/
  описания сцен; деление на «акты» — отдельным шагом на основе транскрипта.
- **Персистентность:** перенести на сервер — **PostgreSQL** (Prisma/Drizzle) для
  прогонов, персон, ответов, отчётов (нужно для воспроизводимости и истории).
  На MVP можно временно оставить localforage.

**Альтернатива** (если приоритет — минимум переписывания): оставить `agora` на
Vite+Express как базу и достраивать агентов там же. Минус — Vite+Express менее
удобны как единый прод-каркас, чем Next.js. Это решение №1, которое зафиксируем.

### Рекомендация по базе для объединения
Взять **`agora`** как базу инфраструктуры (реальный бэкенд + видео-анализ + переключение
провайдеров), **перенести из `Agora-latest`** модель 5-критериев (`SurveyResponse`,
`averageScores`), структуру `lib/ai.ts`/`lib/db.ts` и фичу новостей. `agora-12-main`
можно не трогать — он дублирует `Agora-latest` в более старом виде.

## 6. Безопасность — обязательно перед пушем

1. **Отозвать и перевыпустить** оба захардкоженных ключа (timeweb в `lib/ai.ts`;
   фолбэк-Gemini в `api/index.ts`). Считать их скомпрометированными.
2. Убрать `dangerouslyAllowBrowser: true` — LLM-вызовы должны идти с сервера, ключ
   не должен попадать в браузер.
3. Все секреты — через `.env` (`.env.example` уже есть в `Agora-latest`), добавить
   в `.gitignore`.
4. При создании нового репозитория история старых репо содержит ключи — либо
   **начинать новый репо с чистой истории** (без старых коммитов), либо чистить
   историю. Рекомендую чистый старт.

1. Зафиксировать решения §8 (каркас, база, БД).
2. Собрать новый репозиторий: `agora` как база + перенос 5-критериев и структуры из

   end-to-end, на реальном видео-анализе.

5. Изоляция: перевести симуляцию на независимые вызовы по каждому из 20 агентов

6. Content Processor: транскрипт + деление на акты + описание сцен.
7. QA-агент: проверка консистентности ответов профилю.
8. Analytics-агент: агрегация + нарративный отчёт в UI.
9. Персистентность на сервере (Postgres), seed для воспроизводимости.
