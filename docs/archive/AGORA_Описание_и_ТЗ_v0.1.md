# AGORA — Описание проекта и черновик ТЗ (v0.1)

**Статус:** черновик на основе брифа. Составлен ДО доступа к коду трёх репозиториев
(`agora`, `agora-12-main`, `Agora-latest`). Разделы, помеченные ⚠️, будут уточнены
после чтения реального кода.

**Дата:** 22.07.2026

---

## 1. Что это за продукт

AGORA — это мультиагентный пайплайн, который по заданным социодемографическим
параметрам генерирует **синтетическую аудиторию из AI-агентов** (цифровых двойников
зрителей) и прогоняет её через просмотр видеоконтента. По сути — цифровой аналог
офлайн фокус-группы: 20 синтетических персон «смотрят» ролик/серию и оценивают его
по фиксированным критериям, а система агрегирует ответы в статистику и нарративный
отчёт.

**Зачем:** быстро и дёшево получить прогноз реакции целевой аудитории на контент
(сериал, рекламу, эпизод) до реального проката/теста, с разбивкой по сегментам ЦА.

**Ключевая ценность:** воспроизводимость, скорость, управляемость состава аудитории
и объяснимость (у каждой оценки есть «личность» с мотивацией, а не безликое число).

---

## 2. Критерии оценки (анкета)

Каждая из 20 персон после просмотра заполняет анкету. Все оценки — по шкале **1–10**
(1 — совсем не понравилось, 10 — очень понравилось):

1. **Общее впечатление** от серии.
2. **Сюжет.**
3. **Игра актёров.**
4. **Музыка / музыкальное сопровождение.**
5. **Качество съёмок.**

К каждой числовой оценке агент даёт короткое текстовое обоснование «от лица персоны»
(это нужно и для отчёта, и для проверки консистентности QA-агентом).

---

## 3. Роли агентов

| Агент | Роль | Вход | Выход |
|-------|------|------|-------|
| **Orchestrator / Координатор** | Управляет всем прогоном: инициирует генерацию персон, раздаёт задачи, изолирует ответы агентов друг от друга, собирает результаты. | Параметры ЦА + контент | Управляющие вызовы, финальный сбор |
| **Content Processor / Обработка видео** | Извлекает транскрипт, делит на акты, описывает сцены — превращает видео в структурированный «материал для просмотра». | Видеофайл / ссылка | Транскрипт, разбивка на акты, описания сцен |
| **Persona Generator** | Генерирует уникальные психологические профили на основе параметров ЦА. | Параметры ЦА, N=20 | 20 профилей Persona DNA |
| **Persona DNA** (артефакт, не агент) | Структурированный профиль персоны: 30+ параметров личности, 5-факторная модель (Big Five), нарратив. | — | JSON-профиль |
| **Respondent / Агент-респондент** | Синтетический зритель: «смотрит» обработанный контент через призму своей Persona DNA и заполняет анкету (5 оценок + обоснования). | Persona DNA + материал | Заполненная анкета |
| **QA / Верификация** | Проверяет консистентность ответов респондентов с их профилями (не противоречит ли оценка личности), помечает аномалии. | Persona DNA + ответы | Флаги/оценка качества |
| **Analytics / Аналитик** | Агрегирует все ответы, строит статистику (средние, распределения, сегменты) и генерирует нарративный отчёт. | Ответы 20 персон | Метрики + текстовый отчёт |

**Изоляция ответов** (важное требование): каждый респондент отвечает независимо,
не видя ответов других персон и общего контекста прогона — иначе теряется
разнообразие «мнений». Это закладывается в оркестратор.

## 4. Поток данных (пайплайн)

```
[Параметры ЦА] ──┐
                 ▼
        Orchestrator (координатор)
          │            │
          ▼            ▼
  Persona Generator   Content Processor
          │            │
     20× Persona DNA   Транскрипт + акты + сцены
          │            │
          └──────┬─────┘
                 ▼
     20× Respondent Agent  (изолированно, параллельно)
                 │  5 оценок (1–10) + обоснования на персону
                 ▼
            QA Agent (проверка консистентности)
                 │  валидные ответы + флаги
                 ▼
          Analytics Agent
                 │
                 ▼
   [Статистика + нарративный отчёт]  →  UI
```

Принцип реализации (из практики надёжных пайплайнов): сначала прогнать **одну**
персону сквозь весь пайплайн end-to-end и проверить результат, только потом
масштабировать до 20 параллельно.

## 5. ТЗ: технологический стек

### 5.1 Ключевое решение по языку

Проект естественно распадается на два слоя, и оптимальный язык у них разный:

- **Фронтенд / UI** — уже существует (ключевой репозиторий `agora` имеет интерфейс;
  в папке присутствует артефакт сборки `.next`, что указывает на **Next.js /
  React / TypeScript**). ⚠️ Подтвердить по коду. Рекомендация: **оставить Next.js
  (App Router) + TypeScript + Tailwind** и не переписывать.
- **Ядро агентов / пайплайн** — здесь два разумных пути:

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **A. Python-бэкенд** (рекомендуется для ядра) | Лучшая экосистема LLM-оркестрации (LangGraph), структурированный вывод (Pydantic + instructor), готовая статистика (pandas/numpy/scipy) для Analytics-агента, обработка видео (ffmpeg, whisper) | Смешанный стек: два языка, чуть сложнее деплой |
| **B. Единый TypeScript** (Node + Vercel AI SDK) | Один язык на весь монорепо, проще найм/поддержка, общие типы фронт↔бэк | Слабее для статистики и media-обработки, меньше зрелых agent-фреймворков |

**Рекомендация:** гибрид — **Next.js/TS для UI + API-шлюза**, **Python/FastAPI для
ядра агентов**. Причина: Analytics-агенту нужна нормальная статистика, а Content
Processor'у — media-стек (whisper/ffmpeg), где Python сильнее. Если приоритет —
простота и один язык, вариант B тоже рабочий; это первое решение, которое нужно
зафиксировать вместе.

### 5.2 Предлагаемый стек (при гибридном варианте A)

- **Frontend:** Next.js (App Router) + TypeScript + Tailwind + shadcn/ui.
- **API / шлюз:** Next.js Route Handlers (или tRPC) → проксирует в Python-сервис.
- **Ядро агентов:** Python 3.12 + **FastAPI** + **LangGraph** (граф оркестрации) +
  **Pydantic v2** (схема Persona DNA и структурированные ответы).
- **LLM-слой:** провайдер-агностичная обёртка (Anthropic Claude / OpenAI),
  структурированный вывод через function calling / JSON-schema.
- **Обработка видео:** `ffmpeg` (аудиодорожка/кадры) + **Whisper** (транскрипт) +
  vision-модель (описание сцен).
- **Асинхронность/масштаб:** очередь задач (**Celery + Redis** или лёгкий вариант
  на `asyncio` с семафором) — 20 респондентов гоняются параллельно с лимитом
  конкурентности и ретраями.
- **Хранилище:** **PostgreSQL** (прогоны, персоны, ответы, отчёты) + объектное
  хранилище (S3-совместимое) для видео/транскриптов. Опционально `pgvector` для
  похожести персон.
- **Наблюдаемость:** трейсинг LLM-вызовов (LangSmith / собственные логи), чтобы
  видеть, что «думал» каждый агент.

### 5.3 Модель данных Persona DNA (черновик схемы)

```jsonc
{
  "id": "uuid",
  "run_id": "uuid",
  "socio": {                 // из параметров ЦА
    "age": 34, "gender": "f", "geo": "город-миллионник",
    "income": "средний", "education": "высшее", "occupation": "…"
  },
  "big_five": {              // 5-факторная модель, 0..1
    "openness": 0.7, "conscientiousness": 0.4,
    "extraversion": 0.6, "agreeableness": 0.5, "neuroticism": 0.3
  },
  "traits": { /* 30+ параметров: ценности, вкусы, медиапривычки,
                 любимые жанры, триггеры, толерантность к насилию,
                 темп внимания, эмоциональность и т.д. */ },
  "viewing_habits": { /* как смотрит, что раздражает, что цепляет */ },
  "narrative": "Связный текстовый портрет персоны от 1-го/3-го лица",
  "seed": 123456            // для воспроизводимости
}
```

⚠️ Точный список 30+ параметров зафиксируем после сверки с тем, что уже реализовано
в репозиториях (чтобы не расходиться с существующим форматом).

## 6. Структура проекта (предлагаемая, монорепо)

```
agora/
├─ apps/
│  ├─ web/                  # Next.js UI (существующий интерфейс)
│  └─ api-gateway/          # тонкий шлюз (если не совмещать с web)
├─ services/
│  └─ agent-core/           # Python: FastAPI + LangGraph
│     ├─ orchestrator/
│     ├─ agents/
│     │  ├─ persona_generator.py
│     │  ├─ content_processor.py
│     │  ├─ respondent.py
│     │  ├─ qa.py
│     │  └─ analytics.py
│     ├─ schemas/           # Pydantic: PersonaDNA, Survey, Report
│     ├─ pipeline/          # граф прогона, изоляция, конкурентность
│     └─ prompts/           # промпты по агентам (версионируемые)
├─ packages/
│  └─ shared-types/         # общие типы фронт↔бэк (генерация из схем)
├─ infra/                   # docker-compose, миграции БД, деплой
├─ docs/                    # это ТЗ, ADR-решения, схемы
└─ README.md
```

Инструмент монорепо: **pnpm workspaces + Turborepo** для JS-части; Python-сервис
как отдельный контейнер. ⚠️ Итоговая структура зависит от того, как устроены
существующие три репо — подгоним при объединении.

## 7. План реализации по этапам

1. **Сверка (разблокируется вашим действием).** Прочитать три репо, зафиксировать
   что реально есть в каждом варианте, выбрать «базу» (ключевой — `agora` с UI),
   разметить пересечения и лучшие куски из `agora-12-main` и `Agora-latest`.
2. **Фиксация решений.** Язык ядра (A/B), формат Persona DNA, схема анкеты и отчёта.
3. **Тонкий вертикальный срез.** 1 персона → 1 ролик → анкета → отчёт, end-to-end.
4. **Масштаб до 20** персон с изоляцией и параллелизмом.
5. **Content Processor** (транскрипт/акты/сцены) в полном объёме.
6. **QA-агент** и метрики консистентности.
7. **Analytics-агент**: статистика + нарративный отчёт, вывод в UI.
8. **Объединение в новый репозиторий** и загрузка.
