# AGORA — PRD v1.3

**Продукт:** self-host сервис синтетических фокус-групп для оценки видеоконтента.
**Дата:** 23.07.2026 · **Заменяет:** PRD v1.2.
**Изменения v1.3:**
- Обновлена методология построения синтетических персон из grounding-корпуса (§10.5),
  с учётом пересобранного датасета (пол/съёмки/сегмент — 100%, новый слой
  `focus_group_verbatims`).

**Принцип:** только явные сущности, атрибуты и потоки данных.

---

## 1. Обзор и цель

AGORA генерирует синтетическую аудиторию из AI-персон по соцдем-параметрам, прогоняет
через них видео и выдаёт аналитический отчёт — усреднённо по аудитории и по каждой
персоне. Пользователь: команды/студии (MVP, мультиарендно). Достоверность обеспечивается
заземлением на факты видео (транскрипт + разбор сцен), портрет аудитории и **реальный
grounding-корпус** (165 карточек респондентов, verbatim-цитаты, дискуссии фокус-групп).

## 2. Критерии оценки
Пять обязательных 1–10: общее впечатление, сюжет, игра актёров, музыка, качество съёмок.
Плюс расширяемая анкета (§5.4) и расширенные метрики восприятия (§10.1).

## 4. Архитектура

**Frontend (TS):** Next.js (App Router) — UI, визард (XState), API-шлюз, отчёт,
Промпт-студия, редактор портретов.

**Backend/ингест (Python):** FastAPI + ffmpeg, WhisperX (Whisper large-v3),
pyannote.audio 3.1, VLM, оркестрация **LangGraph**. Связь с UI — Redis + SSE/WebSocket.

**Модели (периметр РФ / open-source):** Whisper large-v3, pyannote, Qwen2.5-VL /
GigaChat-vision, Qwen big-context / GigaChat-Max. Gemini — опц. legacy.
**SimTube — референс, не зависимость.**

**Хранилища:** PostgreSQL+RLS (арендаторы, персоны, портреты, промпты, анкеты, отчёты,
task), MongoDB (chunk JSON, ответы персон, датасет, черновики), Redis/Valkey (очередь/
прогресс/кэш), **S3 (объектное хранилище TimeWeb) — видео/аудио/кадры**. Развёртывание —
Docker Compose на VPS + managed-БД (§15). **TypeDB не используется (§7.6).**

### 10.3 Контексты 4 сериалов
Как в §10.3 v1.2 (Константинополь / Ландыши / Сестра / Тюремный дневник — города,

### 10.4 Логика склейки
XLS (соцдем, баллы, восприятие, verbatims, полная анкета) × DOCX (объект, метаданные
эксперимента, групповые цитаты `focus_group_verbatims`) по ключу
`(сериал × город × сегмент)`. Промпт `dataset.unification` (реестр, §14).

### 10.5 Как строить синтетические персоны из корпуса (МЕТОДОЛОГИЯ)

Датасет — это **grounding-корпус, а НЕ 1:1 источник персон**. Правильный путь:

1. **Распределения по сегментам.** Группировать по `(сериал × город × target_audience_
   segment)` → извлекать реальные доли: возраст/age_group, гео, пол, ценности. Синтетические
   персоны **сэмплируются по этим пропорциям**, а не выдумываются равномерно — это лечит
   mode collapse. Сегмент теперь заполнен (100%), поэтому распределения строятся уже с
   учётом отношения к контенту (напр. «Враждебная» vs «Дружественная», отношение к СВО).
2. **Калибровка оценок.** Реальные средние и дисперсию по каждому критерию (overall 6.6,
   plot 6.7, acting 7.3, music 7.0, cinematography ~7–8; разброс 2–9) использовать как
   **приоры поведения оценивания** — чтобы синтетика не занижала разброс и не завышала всё
   в 10. Cinematography теперь имеет реальный якорь (дыра устранена).
3. **Стилевое и аргументативное заземление.** В промпт Persona DNA / Respondent инжектить
   2–3 цитаты из `qualitative_verbatims` + 2–3 из **`focus_group_verbatims`** (живые
   реплики, споры, аргументы) → персона «говорит» и **спорит** как реальный респондент
   своего сегмента, а не как вежливый ассистент (борьба с sycophancy).
4. **Ценности → DNA.** `psychographics_and_values.important_values` (ВЦИОМ) ложатся прямо
   в поле values Persona DNA.
5. **Сегмент-ориентированная генерация** (замена старого пункта «дыры»). Все 4 дыры
   устранены (пол, cinematography, segment — 100%). Теперь:
   - пол — можно брать реальное распределение (66.7/33.3), НО пользователь может
     переопределить % м/ж на шаге «Аудитория» (приоритет ввода пользователя);
   - `target_audience_segment` задаёт установку персоны к контенту (лояльность/критичность,
     отношение к теме) — прямо влияет на тон и баллы;
   - все 5 критериев (вкл. cinematography) имеют реальный якорь калибровки.
6. **Приватность/обобщение.** Генерим правдоподобного **представителя сегмента**, а не
   копию конкретного респондента. Реальные записи → распределения + стилевые образцы,
   не прямое воспроизведение персональных данных.

**Поток данных:** `grounding_dataset` (Mongo) → агрегация распределений и цитат по
сегментам → авто-черновики `audience_portraits` (.md) → Persona Generator сэмплирует
Persona DNA по портрету + инжектит verbatim-образцы → персоны сохраняются в `persona_set`.

## 15. Инфраструктура и деплой (TimeWeb Cloud)

### 15.1 Компоненты
| Слой | Выбор TimeWeb | Комментарий |
|---|---|---|
| Frontend | **Next.js** (Node.js 24) | = agora-unified |
| Backend/ингест | **FastAPI** (Python 3.14) | ffmpeg/Whisper/pyannote/VLM/LangGraph; Celery-воркеры внутри compose |
| Оркестрация контейнеров | **Docker Compose** на VPS | мультисервис (app + воркеры) |
| БД (managed) | **PostgreSQL 18**, **MongoDB 8.0**, **Valkey (Redis) 9.1** | Kafka/CH/OpenSearch/Neo4j не нужны |
| Объектное хранилище | **S3 (TimeWeb), 100 ГБ, тариф «Стандартный»** | видео/аудио/кадры; кадры чистятся после анализа, оригиналы позже в «Холодный» |

### 15.2 Сайзинг VPS

**Вариант A — CPU-only (рекомендуется на старт MVP).** VLM/LLM — через API (GigaChat/
YandexGPT в периметре РФ), Whisper large-v3 (faster-whisper/CTranslate2 int8) + pyannote —
на CPU.
- **8 vCPU / 16 ГБ RAM / 100 ГБ NVMe.**
- Разбивка: OS+Docker ~15 ГБ; модели Whisper+pyannote ~5–8 ГБ; рабочий scratch (видео
  700 МБ + кадры + аудио на несколько параллельных task) ~20–40 ГБ; логи/буфер. Media —
  в S3, локально только временные файлы.
- RAM: Whisper large-v3 ~3–5 ГБ + pyannote ~2–4 ГБ + Node/FastAPI ~2 ГБ + запас.
- ⚠️ Whisper large-v3 на CPU для 50-мин ролика идёт долго (десятки минут). Для скорости —
  либо GPU (вариант B), либо облачный STT (Yandex SpeechKit).

**Вариант B — с GPU (self-host Whisper + Qwen2.5-VL).** Нужен, если не хотим зависеть от
внешних API для разбора кадров/рассуждения.
- **GPU: 24 ГБ VRAM** (RTX 3090/4090 / A5000 / A10) — Qwen2.5-VL-7B (кванты) + Whisper.
- **Хост: 16 vCPU / 32–64 ГБ RAM / 200 ГБ NVMe.**

**Рекомендация:** стартовать с **A (8 vCPU / 16 ГБ / 100 ГБ NVMe, S3 100 ГБ Standard,
managed Postgres18/Mongo8/Valkey9)**; при росте объёма/скорости и переходе на self-host
моделей — добавить GPU-ноду (B) и апгрейд до 16 vCPU / 32 ГБ.

### 15.3 Топология
`VPS (Docker Compose: Next.js + FastAPI + Celery-воркеры)` → managed Postgres/Mongo/Valkey
(отдельные сервисы TimeWeb) + S3 (медиа) + внешние API моделей (или GPU-нода для self-host).
Секреты — только из env. Новый репозиторий — с чистой истории.
