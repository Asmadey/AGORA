# 🔎 Code Reviewer (Total Review Multi-Agent Suite)

Система глубокого код-ревью на базе методологии **Total Review** с параллельным запуском конкурирующих моделей (Claude + OpenAI Codex), фильтрацией субъективного оверсинкинга (ложных придирок LLM), шортлистом подтверждения и проверкой правок через `no-mistakes`.

Проверьте наличие плана задачи в [.agent/PLANS.md](.agent/PLANS.md) или тикета задачи для проверки соответствия контрактам.

### Шаг 2: Параллельный запуск двух воркеров (Dual-Model Execution)

Запустите двух независимых ревьюеров в параллели:
1. **Worker 1 (Claude / Subagent):** анализ архитектуры, целостности состояния, утечек ресурсов и логики.
2. **Worker 2 (OpenAI Codex CLI):** независимый аудит через [codex-plugin-cc](file:///Users/asmadey/AntiGravity/PersonalOS/skills/public/dev/codex-plugin-cc/SKILL.md) конкурирующей моделью:
   ```bash
   node skills/public/dev/codex-plugin-cc/scripts/run-codex.mjs --prompt "<нейтральный промпт>"
   ```

> 🛡️ **Инвариант нейтрального промпта (Unbiased Prompt Protocol):**
> Категорически запрещено подсказывать ревьюерам предполагаемые баги (например: *«проверь, нет ли тут утечки памяти»*). Наводящие вопросы провоцируют галлюцинации LLM.
> **Каноничный нейтральный шаблон промпта:**
> ```text
> Проведи независимый код-ревью предоставленного диффа.
> Ищи ТОЛЬКО реальные критические дефекты: функциональные баги, нарушение контрактов API, уязвимости безопасности, регрессии тестов, падения в runtime.
> ИГНОРИРУЙ: вкусовщину форматирования, предложения переписать работающий код, теоретические крайние случаи без вероятности в проде.
> Формат ответа: краткий список (файл:строка — суть бага — доказательство).
> ```

*Fallback (Single-Model Mode):* если Codex CLI или субагенты недоступны, хост-агент проводит два изолированных прохода внутри сессии (Pass A: Architecture/Logic + Pass B: Security/NFR).

### Шаг 3: Беспощадный триаж (Ruthless Triage & Deduplication)

1. **Дедупликация:** Если дефект найден обоими воркерами, ему присваивается наивысший приоритет и метка `[both]`. Консенсусные баги почти всегда реальны.
2. **Матрица дисквалификации оверсинкинга:**

| Тип замечания | Классификация | Решение |
| :--- | :--- | :--- |
| Runtime Crash (NullPointer, unhandled Promise, panic) | Реальный дефект | ✅ **В шортлист** |
| Уязвимость (XSS, SQLi, утечка секретов, небезопасный regex) | Реальный дефект | ✅ **В шортлист** |
| Логическая ошибка (нарушение условия бизнес-логики, гонка) | Реальный дефект | ✅ **В шортлист** |
| Споры о синтаксисе (`for` vs `map`, `ternary` vs `if`) | Оверсинкинг | ❌ **DROP** |
| Предложения «вынести интерфейс / создать фабрику на будущее» | Оверсинкинг / оверинжиниринг | ❌ **DROP** |
| Теоретический edge-case с вероятностью 0.0001% без влияния на прод | Оверсинкинг | ❌ **DROP** |
| Отсутствие JSDoc / комментариев на очевидных функциях | Оверсинкинг | ❌ **DROP** |

---

### Шаг 4: Вывод пользователю (Low-Token Shortlist & Approval Gate)

Вывод должен быть лаконичным, в 1 строку на дефект, без сырых логов:

```markdown
### 📋 Результаты Total Review

1. `[both]` **src/auth/session.ts:42** — Срок жизни токена проверяется через `<`, а не `<=`. Возможен пропуск истекших сессий.
2. `[claude]` **src/api/orders.ts:88** — Отсутствует обработка случая, когда корзина пуста при вызове checkout (500 Error).
3. `[codex]` **src/components/UserAvatar.tsx:19** — Не экранируется аватар пользователя при передаче в image loader.

*(Отброшено как оверсинкинг: 6 замечаний по стилю, комментариям и абстракциям)*

---
👉 **Подтвердите действие:**
- Ответьте `all` — исправить все пункты.
- Укажите номера через запятую (например, `1, 3`) — исправить выборочно.
- Ответьте `none` — отклонить замечания и закрыть ревью без изменений.
```

---

### Шаг 5: Исправление и верификация через `no-mistakes`

1. **Строгая изоляция правок:** исправляются **ТОЛЬКО** одобренные пользователем номера. Запрещено попутно менять не относящийся к багам код.
2. **Верификация через [no-mistakes](file:///Users/asmadey/AntiGravity/PersonalOS/skills/public/dev/no-mistakes/SKILL.md):**
   ```bash
   # Прогон локального гейта качества и регрессионных проверок
   pnpm test
   # или запуск гейта no-mistakes
   ```
3. **Фиксация и пуш:**
   ```bash
   git add <измененные-файлы>
   git commit -m "fix(review): устранение дефектов после total-review"
   ```
